# Lecture 4 故事线：从"词是符号"到"词有坐标"

> **Source:** `lecture_4_W26.pdf`
> **核心主题：** 如何让计算机理解词的含义？—— 从查字典到从上下文自动学习
> **故事线：** 从频率方法的"语义盲区"出发，一路攻克"无语义"、"稀疏高维"、"训练太慢"、"OOV"四个boss，最终预告上下文嵌入的新时代。

---

## 🎬 序幕：计算机如何"理解"一个词？

### 核心挑战

人类看到 "happy" 和 "glad"，立刻知道它们意思差不多。但计算机看到的是两串字符——和 "volcano" 一样无关。

**如何让计算机知道 "happy" ≈ "glad" ≠ "volcano"？**

上周（Week 3）我们学了频率方法——One-Hot Encoding、BOW、TF-IDF。它们都把词转成数字。但这些数字只编码了"出现次数"，完全没有**含义**。

> 💡 **频率方法像电话号码：** 每个人有一个唯一号码（独热编码），但号码之间没有"距离"的概念。号码 12345 和 12346 虽然数字接近，但对应的人可能毫无关系。我们需要的是 **GPS 坐标**——位置接近的人确实相邻。

---

## 📚 第一章：频率方法的四大致命缺陷（❌ 全面失败）

### 1.1 四大缺陷

| 缺陷       | 说明                                               | 类比                         |
| ---------- | -------------------------------------------------- | ---------------------------- |
| **高维**   | 词表50,000 → 向量50,000维                          | 用50,000维的空间存储一个词   |
| **稀疏**   | 每个向量只有1个非零值                              | 一本50,000页的书只写了1个字  |
| **无语义** | "happy" 和 "glad" 距离 = "happy" 和 "volcano" 距离 | 同义词在地图上和无关词一样远 |
| **OOV**    | 没见过的词无法表示                                 | 词典里没有的词 = 不存在      |

### 1.2 WordNet 的尝试与不足

WordNet 试图手动编码词语关系：dog IS-A animal, wheel PART-OF car, hot OPPOSITE cold。

但 WordNet 是**手工维护的**：

- 覆盖不全（缺少新词、俚语、专业术语）
- 不可计算（告诉你 "dog IS-A animal"，但不给你向量）
- 静态的（语言在进化，WordNet 不会自动更新）

> 🔑 **故事转折点：** 手动编码词语关系太慢、太不完整。我们需要一种方法**自动从大量文本中学习**词的含义 → **词嵌入**登场！

---

## 🧠 第二章：分布假说——含义来自上下文（✅ 理论突破）

### 2.1 核心洞察

> **"You shall know a word by the company it keeps."** — J.R. Firth, 1957
>
> "你可以通过一个词的同伴来了解它。"

如果 "cat" 和 "dog" 经常出现在相同的上下文中——"feed the **_"、"the _** is sleeping"、"cute little \_\_\_"——它们一定有相似的含义。

这就是**分布假说（Distributional Hypothesis）**：出现在相似上下文中的词具有相似含义。

### 2.2 从假说到实现

**分布假说 → 词嵌入：** 把每个词映射为一个稠密的低维向量 f: V → Rᵈ（通常 d=50~300）。在这个"含义空间"中，含义相近的词位置接近。

**验证标志：** king - man + woman ≈ queen。嵌入空间编码了"皇室"这个抽象概念作为一个**方向**。

> 💡 **GPS坐标类比：** OHE给词分配电话号码，词嵌入给词分配GPS坐标。坐标相近的词含义相似。你甚至可以算"方向"——从man到king的方向就是"皇室"。

---

## 🎯 第三章：Word2Vec——从上下文学习含义（✅ 解决无语义，⚠️ 新问题出现）

### 3.1 自监督的核心思想

**不需要人工标注！** 训练信号来自文本本身——让模型预测缺失的词。

两种架构：

```
CBOW（连续词袋）：          Skip-gram（跳字模型）：
  上下文 → 预测中心词           中心词 → 预测上下文

  "The ___ sat on the mat"     "cat" → {The, ?, sat, on}
   → predict "cat"              → predict surrounding words
```

### 3.2 CBOW vs Skip-gram

|  维度  |      CBOW       |      Skip-gram      |
| :----: | :-------------: | :-----------------: |
|  方向  |  上下文→中心词  |    中心词→上下文    |
|  速度  | 更快（1个预测） |  更慢（多个预测）   |
| 高频词 | ✅ 更好（平滑） |      ⚠️ 有噪声      |
| 低频词 |   ❌ 被平均掉   | ✅ 更好（独立信号） |

> 💡 **填空游戏类比：** CBOW是"完形填空"——从上下文猜中心词。Skip-gram是"扩展联想"——从一个词猜它的邻居。两者都迫使模型理解词的含义。

### 3.3 关键洞察：向量就是权重

训练完成后：

- ❌ 不要网络的输出（预测结果）
- ✅ 要的是隐藏层的**权重矩阵**

每一行就是一个词的向量！训练目标（预测上下文）只是一个**借口**——真正的产品是权重。

### 3.4 ❌ Softmax 瓶颈

原始 Skip-gram 的输出层用 softmax 计算所有词的概率：

```
P(context_word | center_word) = exp(score) / Σ_all_V exp(score_v)
```

词表有50,000个词 → **每个训练样本都要对50,000个词求和** → 极慢！

> 🔑 **故事转折点：** Word2Vec的思想是对的，但 softmax 使训练变得不可承受 → **负采样（SGNS）**登场！

---

## ⚡ 第四章：SGNS——50,000选1变5选1（✅ 解决训练速度）

### 4.1 核心简化

**不再问"50,000个词中哪个是正确上下文？"**
**改问"这个（词，上下文）对是真的还是假的？"**

```
原始 softmax：   选择题（50,000个选项）  O(V) per step
负采样 SGNS：    判断题（1个正+5个负）     O(k) per step
```

- 正样本：(apricot, jam) — 真实共现 → 标签=1
- 负样本：(apricot, volcano)、(apricot, democracy)... — 随机配对 → 标签=0
- 训练简单的逻辑回归区分两者

**加速：** O(50,000) → O(5~15)，快了**3000~10000倍**！

### 4.2 采样策略

负样本不是均匀随机的，而是按 f(w)^(3/4) 采样：

- 3/4次方提升低频词的采样概率
- 避免 "the"、"a" 等高频词主导负样本

### 4.3 已解决 vs 遗留问题

| 问题                | 状态                  |
| ------------------- | --------------------- |
| 无语义（OHE的缺陷） | ✅ Word2Vec学到了语义 |
| 高维稀疏            | ✅ 300维稠密向量      |
| 训练速度            | ✅ SGNS解决           |
| 只看局部窗口        | ❌ 全局统计被忽略     |
| OOV（未见过的词）   | ❌ 仍无法处理         |

> 🔑 **故事转折点：** Word2Vec 只通过局部窗口学习，忽视了全局共现统计。有没有方法结合全局信息？→ **GloVe**登场！

---

## 🌐 第五章：GloVe——全局视野（✅ 结合计数与预测，⚠️ OOV仍在）

### 5.1 从局部到全局

Word2Vec 在训练时只看一个个小窗口——"cat sat on" 是一个窗口，"sat on the" 是下一个。它看到的是一棵棵树，不是森林。

GloVe 的做法：

1. **先统计全局：** 构建一个 V×V 的共现矩阵（词i在词j附近出现了几次）
2. **再优化向量：** 学习向量使得 wᵢ · wⱼ = log(共现次数)

```
"I love Programming. I love Math. I tolerate Biology."

共现矩阵 (window=1):
           I  love  Programming  Math  tolerate  Biology
I          0    2        1        1       1         0
love       2    0        1        1       0         0
Prog.      1    1        0        0       0         0
Math       1    1        0        0       0         0
tolerate   1    0        0        0       0         1
Biology    0    0        0        0       1         0
```

### 5.2 GloVe = 两全其美

|   维度   | 基于计数（SVD） | 基于预测（Word2Vec） | GloVe |
| :------: | :-------------: | :------------------: | :---: |
| 全局统计 |       ✅        |     ❌ 只看窗口      |  ✅   |
| 语义优化 |   ❌ 无针对性   |          ✅          |  ✅   |
| 类比能力 |      一般       |          好          | 更好  |

### 5.3 ❌ 遗留问题

GloVe 仍然是**整词级别**的——如果训练数据中没有 "unhappiness"，就得不到这个词的向量。OOV 问题依然存在。

> 🔑 **故事转折点：** 无论 Word2Vec 还是 GloVe，遇到未见过的词就束手无策。有没有办法"猜测"新词的含义？→ **FastText**登场！

---

## 🔬 第六章：FastText——拆词为部件（✅ 解决OOV，⚠️ 终极缺陷浮现）

### 6.1 核心创新：字符 n-gram

FastText 不把 "unhappiness" 当作一个不可分割的原子，而是拆成字符片段：

```
"where" → ⟨wh, whe, her, ere, re⟩ (3-gram)
         + ⟨wher, here, ere⟩ (4-gram)
         + ⟨where⟩ (整词)

词向量 = Σ 所有n-gram向量 + 整词向量
```

### 6.2 OOV 不再是问题

新词 "unhappily"（训练时从未见过）：

- 它的 n-gram："unh", "nha", "hap", "app", "ppi", "pil", "ily"...
- 这些 n-gram 在 "unhappy"、"happily"、"happy" 中都出现过
- → 新词自动获得有意义的向量！

> 💡 **词根类比：** 人类看到陌生词也能猜意思——"un-"(不) + "happy"(快乐) + "-ly"(地) = 不快乐地。FastText用字符n-gram自动做同样的事。

### 6.3 全方位对比

|   维度   | Word2Vec  |   GloVe   |      FastText      |
| :------: | :-------: | :-------: | :----------------: |
|   单位   |   整词    |   整词    |     字符n-gram     |
|   OOV    |  ❌ 不能  |  ❌ 不能  |    ✅ 子词拼接     |
| 拼写错误 | ❌ 无容错 | ❌ 无容错 |   ✅ 共享n-gram    |
|  形态学  |   忽略    |   忽略    |        捕获        |
| 模型大小 |    小     |    小     | 大（存所有n-gram） |

### 6.4 ❌ 所有静态嵌入的终极缺陷

无论 Word2Vec、GloVe 还是 FastText，它们都有一个**不可修复的缺陷**：

> **"bank"（河岸）和 "bank"（银行）永远是同一个向量。**

这就是**上下文不敏感（Context Insensitivity）**——每个词只有一个固定表示。

而且嵌入还从训练数据中学到了**偏见**：

- "Man:Computer_programmer :: Woman:Homemaker" 是 Word2Vec 的真实输出

> 🔑 **故事转折点：** 静态嵌入无法根据上下文调整含义 → 下一代技术——**上下文嵌入**（ELMo、BERT）——给同一个词在不同上下文中分配不同的向量。这是 Week 5+ 的主题。
