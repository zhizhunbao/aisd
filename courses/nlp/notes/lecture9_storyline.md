# Lecture 9 故事线：从静态词向量到 Transformer 架构

> **Source:** `lecture_9_W26.pdf`
> **核心主题：** 如何让一个词的表示"活"起来——从"一个词一个向量"到"每个词根据上下文实时计算向量"
> **故事线：** 从 word2vec 的"一词一义"困境出发，攻克"上下文盲"、"词序盲"、"瓶颈"三个 boss，最终抵达 Transformer 的完整架构。

---

## 🎬 序幕：我们在解决什么问题？

### 核心挑战

考虑一个简单的英语例子：

```
句子1: I went to the bank to deposit money.   (bank = 银行)
句子2: I sat on the bank of the river.         (bank = 河岸)
```

word2vec 给 "bank" 只有**一个固定向量**——无论出现在哪个句子里都一样。这意味着模型**无法区分**金融语境和自然语境中的 "bank"。

> 💡 **上一讲我们已经有了 Bi-LSTM 和注意力机制，知道如何让模型看到上下文。但那些方法的核心仍然是 RNN——顺序处理、速度慢、梯度问题。这一讲要回答一个更根本的问题：有没有一种架构，能完全抛弃循环，同时做到上下文理解？**

### 技术起点

我们已经有的工具：

- **word2vec/GloVe**：静态词嵌入，一词一向量（❌ 无上下文）
- **RNN/LSTM**：时序建模，但顺序处理慢（❌ 不可并行）
- **Bi-LSTM + Attention**：双向上下文 + 动态关注（❌ 仍依赖 RNN 骨架）

本讲的目标：构建一个**不使用任何循环结构**、**纯靠注意力**的全新架构。

## 📚 第一章：静态嵌入的四大致命缺陷（✗ word2vec 为什么不够）

### 1.1 问题诊断

word2vec 的四个致命问题：

| 编号 | 缺陷                              | 具体表现                                      |
| ---- | --------------------------------- | --------------------------------------------- |
| ①    | **一词一义 (Fixed Embeddings)**    | "bank" 不论语境，永远是同一个向量              |
| ②    | **训练后固化 (Fixed at Training)** | 训练完模型后，词向量不会随新语境变化           |
| ③    | **未登录词 (OOV Problem)**         | 训练集中没出现过的词无法表示                   |
| ④    | **词形盲 (Morphological Blindness)** | "run"、"running"、"runner" 被当作三个独立的词 |

> 💡 **类比：** word2vec 就像一本纸质词典——每个词只有一个解释，无论你在什么场景下查它。人类理解语言却是灵活的——根据上下文实时调整理解。

### 1.2 我们需要什么？

**上下文化嵌入 (Contextual Embeddings)：**

- 同一个词在不同句子中应该有**不同的向量**
- 词的含义由**周围的词共同决定**
- 向量应该在**推理时动态计算**，而不是查表

> 🔑 **故事转折点：** 为了获得上下文化嵌入，我们需要一种机制让每个词"观察"它所在句子的所有其他词，并根据相关性动态调整自己的表示 → **自注意力 (Self-Attention)** 登场！

## 🎯 第二章：自注意力机制——让每个词"环顾四周"（✅ 解决上下文盲）

### 2.1 核心直觉

**自注意力回答一个简单的问题：对于句子中的每个词，其他哪些词最有助于理解它？**

```
句子: "The cat sat on the mat because it was tired"

当理解 "it" 时：
  "The"   → 不太相关 (权重 0.02)
  "cat"   → 非常相关！(权重 0.45)  ← "it" 指代 "cat"
  "sat"   → 有些相关 (权重 0.10)
  "on"    → 不太相关 (权重 0.01)
  "the"   → 不太相关 (权重 0.02)
  "mat"   → 有些相关 (权重 0.08)
  "because" → 有些相关 (权重 0.10)
  "was"   → 有些相关 (权重 0.12)
  "tired" → 有些相关 (权重 0.10)
```

"it" 的新表示 = 按这些权重加权混合所有词的信息 → **自动捕获了 "it = cat" 的指代关系** ✅

> 💡 **类比：** 想象一个圆桌会议，每个词是一个参会者。开会时，每个人都会主动"扫视"桌上所有人，然后根据每个人与自己的相关程度来决定"听谁说话、听多少"。这就是自注意力——每个词同时关注所有其他词，按相关性加权吸收信息。

### 2.2 为什么需要多头注意力？

**问题：** 单头注意力只能学到一种关注模式。但语言中存在多种关系——语法（主谓）、语义（指代）、位置（近邻）等。

**解决：** 多头注意力 = 同时运行多个独立的注意力"头"，每个头学习关注不同类型的关系。

```
Head 1: 关注语法关系     "it" → "cat" (主语指代)
Head 2: 关注位置邻近     "it" → "was" (紧邻的词)
Head 3: 关注语义关系     "it" → "tired" (状态描述)
...
最终结果 = 拼接所有 head 的输出
```

> 🔑 **故事转折点：** 自注意力解决了"每个词如何感知上下文"的问题。但完全抛弃了循环结构后，有一个新问题——**词序信息丢失了**。"I love NLP" 和 "NLP love I" 产生完全相同的注意力结果！→ 我们需要**位置编码**！

## 🏗️ 第三章：Transformer 架构——"Attention Is All You Need"

### 3.1 Transformer 的总体设计

2017 年 Vaswani 等人发表 *"Attention Is All You Need"*，提出完全抛弃循环和卷积，仅靠注意力机制构建序列模型。

```
输入序列──→ [ 编码器 Encoder ] ──→ 中间表示 ──→ [ 解码器 Decoder ] ──→ 输出序列
              N层×(自注意力+FFN)                  N层×(掩码注意力+交叉注意力+FFN)
```

编码器（Encoder）和解码器（Decoder）各自堆叠 N 层（论文中 N=6），每层包含：

| 组件            | 编码器                  | 解码器                               |
| --------------- | ----------------------- | ------------------------------------ |
| 注意力          | 自注意力（看全部）      | 掩码自注意力（只看已生成） + 交叉注意力（看编码器输出） |
| 前馈层 (FFN)    | ✅                      | ✅                                   |
| 残差连接        | ✅                      | ✅                                   |
| 层归一化        | ✅                      | ✅                                   |

### 3.2 位置编码——给并行架构注入顺序

**问题：** 自注意力是集合操作（对称的），不区分词的位置。"I love NLP" 和 "NLP love I" 对自注意力来说是一样的。

**解决：** 在词嵌入之上**加入位置向量**，使用正弦/余弦函数：

```
PE(pos, 2i)   = sin(pos / 10000^(2i/d))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d))
```

**为什么用 sin/cos？**

- 不同位置产生**不同的编码模式** → 可以区分位置
- 任意两个位置的编码可以通过**线性变换**相互得到 → 模型能学到相对位置关系
- 可以外推到**训练时未见过的长度** → 泛化能力

**实际例子 "I love NLP"（d=4）：**

| 词   | 位置 | 编码向量                             |
| ---- | ---- | ------------------------------------ |
| "I"  | 0    | [0, 1, 0, 1]                        |
| "love" | 1  | [0.8415, 0.5403, 0.01, 0.9999]      |
| "NLP" | 2   | [0.9093, -0.4161, 0.02, 0.9998]     |

最终输入 = 词嵌入向量 + 位置编码向量

> 💡 **类比：** 词嵌入告诉模型"这个词是什么"，位置编码告诉模型"这个词在哪"。就像一个信封——内容（嵌入）+ 地址（位置）缺一不可。

### 3.3 缩放点积注意力——核心计算引擎

自注意力的完整计算流程（5步）：

```
输入: 每个词 → 三个向量：Query (Q), Key (K), Value (V)

步骤1: 计算相似度分数
    score = Q · K^T         (点积)

步骤2: 缩放
    scaled_score = score / √d_k    (d_k = Key 维度)

步骤3: Softmax 归一化
    attention_weights = softmax(scaled_score)

步骤4: 加权求和
    output = attention_weights · V

步骤5: 送入前馈网络
    final = FFN(output)
```

**为什么要缩放（除以 √d_k）？**

当维度 d 很大时（如 d=64），Q·K 的点积结果的方差也会很大 → softmax 会被推向极端（接近 one-hot）→ 梯度几乎为零 → 训练无法进行。

除以 √d_k 将点积的方差控制在 1 附近 → softmax 输出更平滑 → 梯度健康。

> 💡 **类比：** 缩放就像考试评分时除以满分——如果不除，100分制和10000分制的分数差异巨大，softmax 会被大数值"淹没"。除以 √d 让分数回到合理范围。

### 3.4 前馈层、残差连接与归一化

**前馈层 (FFN)：**

`FFN(Z) = ReLU(Z · W₁ + b₁) · W₂ + b₂`

- 对每个位置**独立**做非线性变换（position-wise）
- 第一层扩展维度（如 512→2048），第二层压缩回来（2048→512）
- 功能：在注意力整合上下文后，FFN 负责**对每个位置独立地做特征变换**

**残差连接 (Residual Connection)：**

`output = LayerNorm(x + Sublayer(x))`

- 每层学习的不是全新的表示，而是在输入基础上做**增量修正**
- 好处：梯度可以直接流过残差路径，解决深层网络的梯度问题

### 3.5 并行计算——Transformer 的工程优势

**RNN 的顺序瓶颈：**

```
RNN:  词₁ → 词₂ → 词₃ → 词₄ → 词₅    (必须等前一个算完)
      1步   2步   3步   4步   5步      → 总共 5 步
```

**Transformer 的并行处理：**

```
Transformer:  词₁  词₂  词₃  词₄  词₅    (所有词同时处理)
               ↕    ↕    ↕    ↕    ↕
             自注意力矩阵乘法 → 1步计算完毕
```

整句的 Q、K、V 矩阵通过矩阵乘法**一次性并行计算**，GPU 利用率从 RNN 的链式调用变成了大规模矩阵运算——速度提升数量级。

> 🔑 **关键对比：** RNN 的计算复杂度是 O(n)（序列长度），且不可并行。Transformer 虽然注意力计算是 O(n²)，但可以完全并行——在 GPU 上实际速度远快于 RNN。

## 🎭 第四章：解码器——从理解到生成

### 4.1 编码器 vs 解码器的核心区别

编码器可以看到整个输入序列（双向的）。但解码器在**生成过程中**不能偷看未来——因为未来的词还没有生成。

### 4.2 掩码自注意力（Masked Self-Attention）

```
生成序列: "I love NLP"

当生成 "love" 时:
  "I"    →  可以看 ✅
  "love" →  当前位置 ✅
  "NLP"  →  还没生成！❌ 必须屏蔽

掩码矩阵:
         I    love   NLP
  I    [ 0     -∞    -∞  ]
  love [ 0      0    -∞  ]
  NLP  [ 0      0     0  ]
```

将未来位置的注意力分数设为 -∞，经过 softmax 后这些位置的权重变为 0，确保解码器只能"往左看"。

> 💡 **类比：** 编码器是开卷考试（可以看到所有参考资料），解码器是闭卷考试（只能用已经写下的答案来推导下一步）。

### 4.3 交叉注意力（Cross-Attention）

交叉注意力是**编码器和解码器之间的桥梁**：

```
解码器提供: Query (Q) ← "我现在在生成什么"
编码器提供: Key (K), Value (V) ← "源序列的完整表示"
```

- 解码器在每一步生成时，通过 Q 去"查询"编码器的 K、V
- 动态决定"当前生成这个词时，源序列的哪些部分最相关"

### 4.4 完整工作流

```
输入: "il a m' entarté" (法语)

编码器:
  层1→层2→...→层6
  每层: 自注意力 → Add&Norm → FFN → Add&Norm
  输出: 所有词的上下文化表示

解码器 (自回归生成):
  START → 层1→...→层6 → softmax → "he"
  START, "he" → 层1→...→层6 → softmax → "hit"
  START, "he", "hit" → ... → "me"
  ...直到生成 END

每个解码器层:
  掩码自注意力 → Add&Norm → 交叉注意力(Q=解码器, KV=编码器输出) → Add&Norm → FFN → Add&Norm
```

最终通过 softmax 在整个词表上输出下一个词的概率分布。

> 🔑 **故事转折点：** Transformer 用编码器理解输入、用解码器自回归生成输出、用交叉注意力桥接两者。这个"全注意力"架构不使用任何循环结构，却能完成翻译、摘要、问答等一切序列任务 → 接下来看它在实际中如何应用。

## 🚀 第五章：Hugging Face 生态与实际应用

### 5.1 Hugging Face——Transformer 时代的操作系统

Hugging Face 提供了一站式的 Transformer 工具生态：

- **Models Hub**：数十万预训练模型一键下载
- **Datasets Hub**：标准数据集开箱即用
- **`transformers` 库**：统一的 API 调用所有模型

### 5.2 只需数行代码——`pipeline()` 四大任务

| 任务               | API 调用                                       | 幕后模型 |
| ------------------ | ---------------------------------------------- | -------- |
| 文本分类           | `pipeline("text-classification")`              | BERT 类  |
| 命名实体识别 (NER) | `pipeline("ner", aggregation_strategy="simple")` | BERT 类  |
| 阅读理解 (QA)      | `pipeline("question-answering")`               | BERT 类  |
| 自动摘要           | `pipeline("summarization")`                    | BART/T5  |

> 💡 **关键认知：** `pipeline()` 背后的流程是：`文本 → tokenizer → 模型推理 → 后处理 → 结果`。一行代码封装了分词、张量转换、模型前向传播、输出解码的全部复杂性。

### 5.3 Transformer 家族三大分支

从 2017 年原始 Transformer 出发，演化出三个方向：

```
                    Transformer (2017)
                          │
            ┌─────────────┼─────────────┐
            │             │             │
      Encoder-only   Encoder-Decoder  Decoder-only
       (仅编码器)    (编码器-解码器)   (仅解码器)
            │             │             │
         BERT (2018)    T5 (2019)    GPT (2018-2024)
         RoBERTa        BART         GPT-2, GPT-3, GPT-4
         ALBERT         mT5         Claude, LLaMA
            │             │             │
      理解任务最强     翻译/总结       生成任务最强
     (分类/NER/QA)  (Seq2Seq 通用)   (对话/创作/推理)
```

## ⚠️ 第六章：Transformer 面临的五大挑战

### 6.1 挑战列表

| 挑战                           | 具体表现                                                         |
| ------------------------------ | ---------------------------------------------------------------- |
| **语言 (Language)**            | 预训练数据以英语为主，低资源语言效果差                           |
| **数据可用性 (Data)**          | 需要海量高质量文本，获取和清洗成本高                             |
| **长文档 (Long Documents)**    | 自注意力 O(n²) 复杂度，512/1024 token 限制                      |
| **透明度 (Transparency)**      | 数十亿参数组成的"黑盒"，难以解释为什么做出特定预测               |
| **偏见 (Bias)**                | 训练数据中的性别、种族、文化偏见会被模型放大                     |

> 💡 **关键认知：** 这些挑战不是"小问题"——它们直接影响 Transformer 在医疗、法律、金融等高风险领域的安全部署。尤其是偏见和透明度问题，是当前 AI 伦理研究的核心议题。
