# Lecture 2 故事线：从乱麻到结构——文本预处理的打怪升级之旅

> **Source:** `lecture_2_W26.pdf` (56 pages)
> **核心主题：** 机器拿到一堆人类写的文字，怎么一步步把它变成能用的干净数据？
> **故事线：** 一场"文本清洗流水线"的组装之旅——每一步都在解决上一步遗留的问题，从最原始的正则匹配到最精细的语义标注

---

## 🎬 序幕：我们要解决什么问题？

### 一句话概括

> 真实世界的文本是一团乱麻——大小写混乱、标点乱飞、HTML 标签、URL、停用词……机器怎么从这堆垃圾里提取有用信息？

**核心矛盾：**

```
人类写的文本：  "Visit https://example.com!!! It's AMAZING... #NLP @professor"
机器需要的输入：  ["visit", "example", "amazing", "nlp", "professor"]
```

从左边到右边，需要经过一整条**预处理流水线 (Preprocessing Pipeline)**。本讲就是在一步步组装这条流水线。

### 为什么这很重要？

> **Garbage in, garbage out.** 预处理决定了模型的天花板。

| 场景             | 不预处理的后果                                          |
| ---------------- | ------------------------------------------------------- |
| **情感分析**     | "AMAZING" 和 "amazing" 被当成两个不同的词，特征空间膨胀 |
| **垃圾邮件检测** | HTML 标签和 URL 干扰分类器，误判率飙升                  |
| **搜索引擎**     | "running"、"runs"、"ran" 无法匹配到同一个查询           |
| **命名实体识别** | 如果先小写化，"Apple"（公司）和 "apple"（水果）无法区分 |

> 💡 一个预处理优秀的普通模型，往往胜过预处理糟糕的最先进模型。真实 NLP 项目 60-80% 的时间花在预处理上。

### 本讲的故事线

```
📖 故事脉络：

NLP三大方法论 → 正则表达式（最古老的武器）→ NLP开发生命周期（全景图）
→ 预处理流水线开始组装：
  分词（第一步）→ 噪声移除（第二步）→ 规范化（第三步）→ POS/NER（第四步）

具体来说：
方法论 → Regex → 生命周期 → Tokenization → Noise Removal → Normalization → POS & NER
```

### 全景图：流水线的四大工位

```
原始文本 "Visit https://example.com!!! It's AMAZING... #NLP"
    │
    ▼
┌──────────────────────────────────────────────────────┐
│ 🔧 工位0: 正则表达式 (Regex)                          │
│   → 你的瑞士军刀，贯穿整条流水线                        │
│   → 用于模式匹配、提取、替换                            │
└──────────────────────────────────────────────────────┘
    │
    ▼
┌──────────────────────────────────────────────────────┐
│ 🔪 工位1: 分词 (Tokenization)                         │
│   → 把连续文本切成一个个 token                          │
│   → "I can't" → ["I", "ca", "n't"]                  │
└──────────────────────────────────────────────────────┘
    │
    ▼
┌──────────────────────────────────────────────────────┐
│ 🧹 工位2: 噪声移除 (Noise Removal)                    │
│   → 去掉大写、数字、标点、停用词、HTML、URL             │
│   → 减少无关特征，降低维度                              │
└──────────────────────────────────────────────────────┘
    │
    ▼
┌──────────────────────────────────────────────────────┐
│ 🔬 工位3: 规范化 (Normalization)                       │
│   → Stemming: "studying" → "studi"（电锯，快但粗）     │
│   → Lemmatization: "better" → "good"（手术刀，慢但准） │
└──────────────────────────────────────────────────────┘
    │
    ▼
┌──────────────────────────────────────────────────────┐
│ 🏷️ 工位4: 标注 (Tagging)                              │
│   → POS: 每个词的词性（名词？动词？）                    │
│   → NER: 识别人名、地名、组织名                         │
└──────────────────────────────────────────────────────┘
    │
    ▼
干净的结构化数据 → 送入模型
```

> 💡 注意：这条流水线**不是固定的**。不同任务需要不同的步骤组合。情感分析保留表情符号，NER 跳过小写化，诗歌分析跳过规范化。**没有万能流水线。**

## 📚 第一章：NLP 的三个时代——从手写规则到深度学习

> **对应 Slides:** Page 3-4
> **为什么先讲这个？** 因为本讲的正则表达式属于"第一个时代"，理解三个时代的演进才能知道正则的定位和局限。

### 1.1 三个时代一览

| 时代                | 方法             | 代表技术                  | 核心思想              |
| ------------------- | ---------------- | ------------------------- | --------------------- |
| **时代1: 启发式**   | Heuristics-Based | Regular Expression        | 人写规则，机器执行    |
| **时代2: 机器学习** | ML-Based         | Supervised / Unsupervised | 从数据中学习规则      |
| **时代3: 深度学习** | DL-Based         | RNN, LSTM, Transformer    | 从数据中学习表示+规则 |

### 1.2 为什么从正则开始？

> 💡 **不要小看简单方法。** 在生产环境中，80% 的文本处理任务（数据清洗、格式验证、模式提取）用正则和简单规则就能完美解决。用 Transformer 提取邮箱地址？杀鸡用牛刀。

**规则系统的优势：**

- 对结构化模式（邮箱、电话、日期、URL）→ 比任何 ML 模型更快、更便宜、更可靠
- 确定性：相同输入永远产生相同输出
- 可解释：规则是人写的，出了问题一眼就能看到

**规则系统的致命问题：**

- ❌ 无法处理歧义（"bank" 是银行还是河岸？）
- ❌ 无法处理未见过的模式
- ❌ 规则数量爆炸——复杂任务需要成千上万条规则

> 🔑 **故事转折点：** 规则系统的"无法处理歧义和未知模式"正是 NLP 从启发式时代走向 ML 时代的根本原因。但在本讲中，我们先把正则这把"瑞士军刀"磨好——它是整条预处理流水线的基础工具。

## 🔧 第二章：正则表达式——预处理流水线的瑞士军刀

> **对应 Slides:** Page 5-20
> **为什么在这里？** 正则表达式是整条预处理流水线的底层工具。分词要用它、噪声移除要用它、规范化也要用它。不先磨好这把刀，后面的工位全开不了工。

### 2.1 一句话定义

> **正则表达式 = 智能版 Ctrl+F。** 普通搜索只能找精确文本，正则能找"模式"——"所有以大写字母开头、以 ing 结尾的词"、"所有邮箱地址"、"所有 URL"。

### 2.2 元字符速查表

正则的"语法"就是一组**元字符（Metacharacters）**——每个符号代表一种匹配逻辑：

| 符号    | 含义                           | 例子                                        |
| ------- | ------------------------------ | ------------------------------------------- |
| `.`     | 匹配任意单个字符               | `beg.n` → begin, begun, beg3n               |
| `[]`    | 匹配集合中的任一字符           | `[wW]oodchuck` → Woodchuck, woodchuck       |
| `^`     | 在 `[]` 内 = 否定；在外 = 行首 | `[^A-Z]` = 非大写；`^Hello` = 以 Hello 开头 |
| `$`     | 行尾                           | `end$` = 以 end 结尾                        |
| `*`     | 前一个字符出现 0 次或多次      | `oo*h!` → oh!, ooh!, oooh!                  |
| `+`     | 前一个字符出现 1 次或多次      | `o+h!` → oh!, ooh!（不匹配 h!）             |
| `?`     | 前一个字符出现 0 次或 1 次     | `colou?r` → color, colour                   |
| `{m,n}` | 前一个字符出现 m 到 n 次       | `a{2,4}` → aa, aaa, aaaa                    |
| `\`     | 转义特殊字符                   | `\.` 匹配真正的句号                         |
| `\|`    | 或                             | `cat\|dog` → cat 或 dog                     |
| `()`    | 捕获组                         | `(ab)+` → ab, abab, ababab                  |

### 2.3 字符类——快捷方式

| 快捷方式 | 等价于          | 含义         |
| -------- | --------------- | ------------ |
| `\d`     | `[0-9]`         | 任意数字     |
| `\w`     | `[A-Za-z0-9_]`  | 任意"词字符" |
| `\s`     | `[ \t\n\r]`     | 任意空白     |
| `\D`     | `[^0-9]`        | 非数字       |
| `\W`     | `[^A-Za-z0-9_]` | 非词字符     |
| `\S`     | `[^ \t\n\r]`    | 非空白       |

> 💡 **记忆技巧：** 小写 = 匹配该类，大写 = 取反。`\d` 匹配数字，`\D` 匹配非数字。

### 2.4 Python 中的正则：`re` 模块

四个核心函数，**必须区分清楚**：

| 函数                 | 行为                             | 返回值            |
| -------------------- | -------------------------------- | ----------------- |
| `re.match(r, s)`     | 只在字符串**开头**匹配           | Match 对象或 None |
| `re.search(r, s)`    | 在字符串**任意位置**找第一个匹配 | Match 对象或 None |
| `re.findall(r, s)`   | 找**所有**不重叠匹配             | 字符串列表        |
| `re.sub(r, repl, s)` | 用 repl **替换**所有匹配         | 新字符串          |

⚠️ **最常见的坑：`match` ≠ `search`**

```python
import re
re.match("cat", "the cat sat")   # → None！因为 "cat" 不在开头
re.search("cat", "the cat sat")  # → <Match: 'cat'>  ✅
```

其他实用函数：

- `re.split(pattern, string)` — 按模式分割字符串
- `re.compile(pattern)` — 预编译模式，提高重复使用效率
- `.groups()` — 返回所有捕获组
- `.span()` — 返回匹配的起止位置

> 💡 **永远用 `r''` 原始字符串！** `\b` 在普通字符串中是退格符，在正则中是单词边界。`r'\b'` 确保反斜杠直接传给正则引擎。

### 2.5 正则的应用场景

正则不只是"学了就忘"的语法——它贯穿整条预处理流水线：

| 应用         | 正则做什么                             |
| ------------ | -------------------------------------- |
| **文本清洗** | 移除 HTML 标签、URL、特殊字符          |
| **分词**     | 按模式切分文本                         |
| **信息检索** | 提取邮箱、电话、日期                   |
| **情感分析** | 识别表情符号、强调模式（"AMAZING!!!"） |
| **语言检测** | 检测字符集（中文字符 vs 拉丁字符）     |

### 2.6 课堂练习解析

**练习 1：检测 URL**

```python
import re
text = "Visit https://www.example.com or http://another-example.org/path/page.html"
urls = re.findall(r'https?://[^\s]+', text)
# → ['https://www.example.com', 'http://another-example.org/path/page.html']
```

**练习 2：提取合法变量名**

```python
text = 'hsdgkjdh;efjewipjrndendrwerji2;;;;8888p9nskdj3905jdkwqld***w3w945{{{{{jwkqs ;weoijrtwioejri'
variables = re.findall(r'[a-zA-Z_]\w*', text)
# → ['hsdgkjdh', 'efjewipjrndendrwerji2', 'p9nskdj3905jdkwqld', 'w3w945', 'jwkqs', 'weoijrtwioejri']
```

> 关键：变量名以字母或下划线开头 `[a-zA-Z_]`，后跟任意词字符 `\w*`。

> 🔑 **故事转折点：** 正则是一把好刀，但它只能做"模式匹配"——找到符合规则的文本片段。真正的 NLP 项目需要一整条流水线，正则只是其中的工具。接下来我们先看看 NLP 项目的全景图，再开始组装流水线。

## 🔄 第三章：NLP 开发生命周期——全景图

> **对应 Slides:** Page 21
> **为什么在这里？** 在开始组装流水线之前，先看看全局——预处理在整个 NLP 项目中处于什么位置？

### 3.1 生命周期七步走

```
需求收集 → 数据收集 → 文本预处理 → 特征提取 → 模型构建 → 评估 → 部署
   │                                                          │
   └──────────── 收集更多数据 / 改进模型（迭代循环）←──────────┘
```

> 💡 **做菜类比：** 需求=食谱，数据收集=买食材，预处理=洗切，特征提取=调味，模型构建=烹饪，评估=品尝，部署=上菜。如果食材没洗干净，再好的厨艺也做不出好菜。

### 3.2 关键洞察

- **NLP 是迭代式的，不是线性的。** 模型很少一次成功，需要反复"评估→收集更多数据→改进"
- **预处理决定天花板。** 真实项目 60-80% 的时间花在预处理上。一个预处理优秀的普通模型 > 预处理糟糕的最先进模型
- **Garbage in, garbage out.** 这不是口号，是血泪教训

> 🔑 **故事转折点：** 全景图告诉我们，预处理是整个 NLP 流水线的第三步，也是最耗时的一步。现在我们正式开始组装这条流水线——第一个工位：分词。

## 🔪 第四章：分词（Tokenization）——流水线的第一刀

> **对应 Slides:** Page 22-28
> **为什么是第一步？** 机器不能处理连续的字符流。必须先把文本切成一个个离散的"token"，后续所有操作才有对象可操作。

### 4.1 一句话定义

> **分词 = 把一串连续文本切成一个个有意义的碎片（token）。** 这些碎片可以是词、子词、甚至字符。

### 4.2 基本术语层次

```
语料库 (Corpus)          ← 所有文档的集合（图书馆）
  └── 文档 (Document)    ← 一个文本单元（一本书）
       └── 段落 (Paragraph)
            └── 句子 (Sentence)
                 └── Token        ← 最小处理单位（一个词/子词）
```

### 4.3 为什么不能简单按空格切？

`text.split(" ")` 看起来简单，但处处翻车：

| 场景         | 问题                                    |
| ------------ | --------------------------------------- |
| `"New York"` | 一个实体被切成两个 token                |
| `"don't"`    | 应该切成 `"do"` + `"n't"`，但空格切不动 |
| `"hello,"`   | 标点粘在词上，`"hello,"` ≠ `"hello"`    |
| 中文/日文    | 词之间根本没有空格                      |

### 4.4 专业分词器

生产环境用专业工具：

| 工具                 | 特点                                |
| -------------------- | ----------------------------------- |
| NLTK `word_tokenize` | 经典，处理缩写和标点                |
| spaCy tokenizer      | 快速，支持多语言                    |
| BPE / WordPiece      | 子词级别，现代模型（BERT、GPT）使用 |

```python
# NLTK 分词示例
from nltk.tokenize import word_tokenize
word_tokenize("I can't wait")
# → ["I", "ca", "n't", "wait"]  ← 注意 can't 被正确拆分
```

> 💡 **词级 vs 子词分词：** 词级把 "unhappiness" 当一个 token。子词（BPE）把它切成 ["un", "happiness"]——这样即使没见过 "unhappiness"，模型也能从 "un" 和 "happiness" 推断含义。这就是现代 LLM 处理未知词的秘密。

> 🔑 **故事转折点：** 文本切好了，但里面全是垃圾——大写字母、HTML 标签、URL、停用词……这些"噪声"会让特征空间爆炸。下一步：清扫垃圾。

## 🧹 第五章：噪声移除（Noise Removal）——清扫流水线上的垃圾

> **对应 Slides:** Page 29-36
> **为什么需要这步？** 分词后的 token 列表里充满了对任务无用的"噪声"。每个噪声 token 都会变成特征空间的一个维度，白白增加计算量、降低模型精度。

### 5.1 什么算"噪声"？

> **噪声 = 与你的 NLP 任务无关的文本元素。** 关键词：**与任务无关**。同一个元素在不同任务中可能是噪声也可能是信号。

### 5.2 噪声移除清单

| 噪声类型  | 操作           | Python 代码                         |
| --------- | -------------- | ----------------------------------- |
| 大写字母  | 统一小写       | `text.lower()`                      |
| 数字      | 移除含数字的词 | `re.sub(r'\w*\d\w*', ' ', text)`    |
| 标点符号  | 移除标点       | `re.sub(r'[^\w\s]', '', text)`      |
| 停用词    | 移除高频无义词 | NLTK `stopwords.words('english')`   |
| HTML 标签 | 移除标签       | `re.sub(r'<[^>]+>', '', text)`      |
| URL       | 移除链接       | `re.sub(r'https?://\S+', '', text)` |
| 多余空白  | 合并空格       | `re.sub(r'\s+', ' ', text).strip()` |

> 注意：这里正则表达式又出场了——第二章磨的刀，现在派上用场。

### 5.3 停用词（Stop Words）详解

停用词是出现频率极高但语义贡献极低的词：the, is, at, which, on...

**为什么要移除？**

- "the" 出现在几乎每个文档中，但对区分文档毫无帮助
- 移除后特征空间维度大幅降低，模型更快更准

**NLTK 停用词示例：**

```python
from nltk.corpus import stopwords
stop_words = set(stopwords.words('english'))
# → {'the', 'is', 'at', 'which', 'on', 'a', 'an', ...}

tokens = ["this", "is", "a", "great", "movie"]
filtered = [w for w in tokens if w not in stop_words]
# → ["great", "movie"]
```

### 5.4 复合词提取（Compound Term Extraction）

有些多词短语应该被当作一个整体：

- "New York" → 不应该被拆成 "New" + "York"
- "machine learning" → 一个概念，不是两个词

复合词提取在噪声移除阶段识别并标记这些短语，防止后续处理破坏它们的完整性。

### 5.5 ⚠️ 噪声移除的致命陷阱

| 陷阱       | 后果                                       | 受影响任务 |
| ---------- | ------------------------------------------ | ---------- |
| 小写化     | "Apple"（公司）→ "apple"（水果），无法区分 | NER        |
| 移除停用词 | "not good" → "good"，含义完全反转          | 情感分析   |
| 移除数字   | "COVID-19" → "COVID-"，信息丢失            | 医学 NLP   |
| 移除标点   | "Dr." → "Dr"，缩写被破坏                   | 文本理解   |

> 💡 **核心原则：没有万能的清洗方案。** 每次清洗前都要问自己："这个元素对我的任务有用吗？" 情感分析保留表情符号和否定词，NER 保留大小写，诗歌分析几乎什么都不删。

> 🔑 **故事转折点：** 垃圾清扫完了，但还有一个问题——"running"、"runs"、"ran" 是三个不同的 token，但它们都是同一个动作。特征空间还是太大了。下一步：把不同形态的词统一成一个。

## 🔬 第六章：规范化（Normalization）——电锯与手术刀

> **对应 Slides:** Page 37-47
> **为什么需要这步？** 英语中一个词有多种形态变化：run/runs/running/ran。如果不统一，它们会被当成四个独立特征，白白膨胀词表约 40%。

### 6.1 一句话定义

> **规范化 = 把词的各种变形统一回基本形式。** 有两种工具：电锯（Stemming）和手术刀（Lemmatization）。

### 6.2 词干提取（Stemming）——电锯

**原理：** 用规则暴力砍掉后缀，不查字典，不管结果是不是真词。

```
studying → studi    （不是真词！）
studies  → studi
running  → run
```

**三种 NLTK 词干提取器：**

| 算法              | 激进程度 | 特点                        |
| ----------------- | -------- | --------------------------- |
| Porter Stemmer    | 最温和   | 最常用，经典                |
| Snowball Stemmer  | 中等     | Porter 的改进版，支持多语言 |
| Lancaster Stemmer | 最激进   | 砍得最狠，可能过度词干化    |

```python
from nltk.stem import PorterStemmer
stemmer = PorterStemmer()
stemmer.stem("studying")   # → "studi"
stemmer.stem("university") # → "univers"
stemmer.stem("universe")   # → "univers"  ← 问题！两个不同概念被合并了
```

### 6.3 词元化（Lemmatization）——手术刀

**原理：** 查词典 + 分析词性，返回词的**标准词典形式（lemma）**。输出永远是真词。

```
am / are / is  → be
better         → good     ← Stemming 做不到这个！
running        → run
```

**关键区别：需要词性信息（POS）**

"meeting" 是名词还是动词？

- 名词 → lemma: "meeting"（会议）
- 动词 → lemma: "meet"（见面）

```python
from nltk.stem import WordNetLemmatizer
lemmatizer = WordNetLemmatizer()
lemmatizer.lemmatize("better", pos='a')  # → "good"  (形容词)
lemmatizer.lemmatize("running", pos='v') # → "run"   (动词)
```

### 6.4 电锯 vs 手术刀——终极对比

| 维度        |                Stemming（电锯）                 | Lemmatization（手术刀） |
| ----------- | :---------------------------------------------: | :---------------------: |
| 速度        |                      ✅ 快                      |          ❌ 慢          |
| 准确性      |              ❌ 低（可能过度切割）              |   ✅ 高（上下文感知）   |
| 输出        |                  可能不是真词                   |       永远是真词        |
| 需要词性？  |                     不需要                      |          需要           |
| 示例        |               "better" → "better"               |    "better" → "good"    |
| 工具 (NLTK) |                  PorterStemmer                  |    WordNetLemmatizer    |
| 致命问题    | "university"/"universe" → "univers"（合并错误） |  需要 POS 信息，速度慢  |

> 💡 **选择指南：** 对精度要求不高、数据量大 → Stemming。对精度要求高、需要语义准确 → Lemmatization。大多数现代 NLP 项目选 Lemmatization。

### 6.5 何时不该规范化？

- **诗歌分析：** 词形携带韵律和节奏信息，"running" 和 "run" 节奏不同
- **社交媒体：** 非标准拼写本身就是特征（"sooooo" 表达强烈情感）
- **计算成本敏感：** 如果数据量极大且精度要求不高，可以跳过

> ⚠️ **考试重点：** "SpaCy 没有内置的 Stemming 功能。" SpaCy 有意只提供 Lemmatization。如果需要 Stemming，必须用 NLTK。

> 🔑 **故事转折点：** 到这里，文本已经被切碎、清洗、统一了。但我们还缺最后一步——给每个词贴上"身份标签"：它是名词？动词？还是一个人名？

## 🏷️ 第七章：词性标注与命名实体识别——给词贴身份标签

> **对应 Slides:** Page 48-53
> **为什么是最后一步？** 前面的工位把文本切碎、清洗、统一了。但机器还不知道每个词的"角色"——它是名词还是动词？是普通词还是人名？POS 和 NER 就是给每个词贴上身份标签。

### 7.1 词性标注（POS Tagging — Part-of-Speech Tagging）

> **POS (Part-of-Speech) Tagging = 给句子中每个词标注语法角色。** 名词(NN)、动词(VB)、形容词(JJ)、副词(RB)……

**为什么重要？** 同一个词在不同语境中词性不同，含义完全不同：

| 句子                          | "book" 的词性 | 含义 |
| ----------------------------- | :-----------: | ---- |
| "I need to **book** a flight" |  VB（动词）   | 预订 |
| "I read a **book**"           |  NN（名词）   | 书   |

```python
import nltk
from nltk import pos_tag, word_tokenize

tokens = word_tokenize("I need to book a flight")
pos_tag(tokens)
# → [('I', 'PRP'), ('need', 'VBP'), ('to', 'TO'),
#    ('book', 'VB'), ('a', 'DT'), ('flight', 'NN')]
```

**Penn Treebank 常用标签：**

| 标签 | 含义           | 例子          |
| ---- | -------------- | ------------- |
| NN   | 名词（单数）   | dog, city     |
| NNS  | 名词（复数）   | dogs, cities  |
| VB   | 动词（原形）   | run, eat      |
| VBD  | 动词（过去式） | ran, ate      |
| JJ   | 形容词         | big, happy    |
| RB   | 副词           | quickly, very |
| PRP  | 人称代词       | I, he, she    |
| DT   | 限定词         | the, a, an    |

> 💡 **POS 是消歧的基础。** "I saw her duck"——"duck" 是名词（鸭子）还是动词（蹲下）？POS 标注器根据上下文判断。这直接关联 Week 1 讲的歧义性挑战。

### 7.2 命名实体识别（NER — Named Entity Recognition）

> **NER (Named Entity Recognition) = 从文本中找出专有名词，并分类为人名、地名、组织名等。** 它建立在 POS 标注之上——先知道一个词是名词，才能判断它是不是命名实体。

**NER 标签类型：**

| 标签           | 含义   | 例子                   |
| -------------- | ------ | ---------------------- |
| PERSON         | 人名   | James Smith            |
| LOCATION / GPE | 地名   | United States, Beijing |
| ORGANIZATION   | 组织名 | Google, MIT            |
| DATE           | 日期   | January 2024           |
| MONEY          | 金额   | $500                   |

```python
from nltk import pos_tag, word_tokenize
from nltk.chunk import ne_chunk

text = "James Smith lives in the United States."
tokens = word_tokenize(text)
tagged = pos_tag(tokens)
entities = ne_chunk(tagged)
# → (PERSON James/NNP Smith/NNP)
# → (GPE United/NNP States/NNPS)
```

### 7.3 POS vs NER 对比

| 维度       | POS Tagging (Part-of-Speech Tagging / 词性标注) | NER (Named Entity Recognition / 命名实体识别) |
| ---------- | :---------------------------------------------: | :-------------------------------------------: |
| 全称       |           **Part-of-Speech Tagging**            |         **Named Entity Recognition**          |
| 中文       |                    词性标注                     |                 命名实体识别                  |
| 处理对象   |              **每个词**的语法类别               |           **特定实体**（专有名词）            |
| 标签       |              NN, VB, JJ, RB, DT...              |       PERSON, ORG, LOC, DATE, MONEY...        |
| 粒度       |                   单个 token                    |            多词跨度（"New York"）             |
| 关注什么   |              语法结构 (syntactic)               |              语义信息 (semantic)              |
| 目的       |                 语法分析、消歧                  |              信息提取、知识图谱               |
| 依赖关系   |                      独立                       |                 需要先做 POS                  |
| 一句话记忆 |     这个词是什么**词性**？（名词？动词？）      | 这个词是什么**实体**？（人名？地名？公司？）  |

### 7.4 ⚠️ 关键陷阱：NER 必须在小写化之前运行

如果你先 `text.lower()`，"Apple"（公司）和 "apple"（水果）就无法区分了。

**正确的流水线顺序：**

```
原始文本 → 分词 → POS 标注 → NER → 然后再小写化/噪声移除
```

> 💡 **这就是为什么说"没有万能流水线"。** 步骤的顺序取决于你需要保留什么信息。NER 任务必须把标注放在清洗之前。

### 各工位核心对比

| 工位     | 输入           | 输出           | 核心工具               | 解决的问题                   |
| -------- | -------------- | -------------- | ---------------------- | ---------------------------- |
| 分词     | 连续文本       | token 列表     | NLTK, spaCy, BPE       | 机器无法处理连续字符流       |
| POS/NER  | token 列表     | 带标签的 token | NLTK pos_tag, ne_chunk | 词的语法角色和实体身份未知   |
| 噪声移除 | 带标签的 token | 清洗后的 token | Regex, stopwords       | 无关特征膨胀特征空间         |
| 规范化   | 清洗后的 token | 基本形式 token | Porter, WordNet        | 同一概念的不同词形占多个维度 |

### 不同任务的流水线定制

| 任务     | 跳过什么         | 保留什么                  |
| -------- | ---------------- | ------------------------- |
| 情感分析 | 跳过移除表情符号 | 保留否定词（not, never）  |
| NER      | 跳过小写化       | 保留大小写                |
| 诗歌分析 | 跳过规范化       | 保留词形（韵律、节奏）    |
| 搜索引擎 | 全部执行         | 用 Stemming 加速          |
| 文本分类 | 全部执行         | 用 Lemmatization 提高精度 |
