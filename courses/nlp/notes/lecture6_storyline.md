# Lecture 6 故事线：从单向记忆到全局注视

> **Source:** `lecture_6_W26.pdf`
> **核心主题：** 如何让机器翻译一个句子？—— 从"只看过去"到"看到全部"再到"同时处理一切"
> **故事线：** 从单向LSTM的"半盲"问题出发，一路攻克"方向盲区"、"信息瓶颈"、"顺序处理"三个boss，最终进化到Transformer。

---

## 🎬 序幕：我们要解决什么问题？

### 核心挑战

给定一个法语句子 "il a m' entarté"，生成对应的英语翻译 "he hit me with a pie"。

这个问题有三个根本难点：

1. **输入输出长度不同** — 法语4个词 → 英语6个词
2. **词序不同** — "entarté"（扔派）在法语末尾，对应的"pie"在英语末尾
3. **需要理解整个输入** — 翻译任何一个词都可能需要看到整个源句子

> 💡 **上周我们学了 RNN 和 LSTM，它们可以处理序列。但翻译不仅仅是"处理序列"——它是"读懂一种语言，用另一种语言重新表达"。这需要全新的架构。**

### 技术起点

我们已经有的工具：

- **N-gram**：用前N-1个词预测下一个词（太短视）
- **RNN**：用隐藏状态传递历史信息（梯度消失）
- **LSTM**：用门控解决长期记忆（✅ 但只看左边）

但这些都是**单向**的——从左到右读。翻译需要更强的能力。

## 📚 第一章：Bi-LSTM——两只眼睛看句子（✅ 解决方向盲区，⚠️ 新问题出现）

### 1.1 问题：单向LSTM的"半盲"

考虑句子 "The movie was terribly exciting!"

单向LSTM处理到 "terribly" 时：

- 已看到：`The movie was` → "terribly" 看起来像**负面词**
- 还没看到：`exciting !` → 实际上 "terribly" 在这里是"非常"（**正面**）

> ❌ **问题核心：** 自然语言中的词义经常取决于**右侧上下文**，而单向LSTM永远看不到右边。

### 1.2 方案：双向读取

**核心思想：** 用两个独立的LSTM同时读句子——一个从左到右，一个从右到左——然后**拼接**两个方向的隐藏状态。

```
正向 LSTM:  The → movie → was → terribly → exciting → !
              h¹→    h²→    h³→     h⁴→       h⁵→    h⁶→

反向 LSTM:  ! → exciting → terribly → was → movie → The
            ←h⁶   ←h⁵       ←h⁴     ←h³   ←h²    ←h¹

拼接结果:   [h→₁;h←₁]  [h→₂;h←₂]  ...  [h→₄;h←₄]  ...
```

在 "terribly" 位置：

- 正向看到了 "The movie was"（语境偏负面）
- 反向看到了 "exciting !"（语境正面）
- **拼接 = 完整图景** → "terribly" = "非常"（正面修饰）

> 💡 **类比：** 两个人读同一个句子——一个从左到右，一个从右到左。每个人理解对方遗漏的部分。在每个词位置比较笔记，就有了完整理解。

### 1.3 代码实现

```python
from tensorflow.keras.layers import Bidirectional, LSTM
# 只需用 Bidirectional() 包装 LSTM 层
Bidirectional(LSTM(n_lstm))
# 输出维度自动变为 2 × n_lstm
```

### 1.4 ❌ Bi-LSTM的限制

|     维度     | 单向LSTM |  Bi-LSTM  |
| :----------: | :------: | :-------: |
|    上下文    | 只看左边 | 看两边 ✅ |
|    参数量    |    n     |    2n     |
| 可用于生成？ |  ✅ 是   |   ❌ 否   |

> 🔑 **关键限制：** Bi-LSTM需要**整个序列预先存在**，因为反向LSTM需要从最后一个词开始。这意味着它**不能用于生成文本**（未来的词还不存在）。用于理解（分类、NER）很好，但翻译的"生成端"不能用Bi-LSTM。

**已解决 vs 遗留问题：**

| 问题                     | 状态           |
| ------------------------ | -------------- |
| 方向盲区（只看左边）     | ✅ Bi-LSTM解决 |
| 输入输出长度不同         | ❌ 仍未解决    |
| 需要理解整个输入后再生成 | ❌ 仍未解决    |

> 🔑 **故事转折点：** Bi-LSTM解决了"看不到右边"的问题，但翻译需要先读完整个源句子再开始生成目标语言。我们需要一种"先理解，再生成"的两阶段架构 → **编码器-解码器（Seq2Seq）**登场！

## 🧮 第二章：Seq2Seq——先读完再翻译（✅ 解决长度不同，⚠️ 瓶颈出现）

### 2.1 核心架构：编码器 + 解码器

```
       编码器 (Encoder)                    解码器 (Decoder)
  ┌──────────────────────┐           ┌──────────────────────┐
  │  il → a → m' → entarté  │──state──→│  he → hit → me → with → a → pie  │
  │  (LSTM从左到右读)      │           │  (LSTM自回归生成)      │
  └──────────────────────┘           └──────────────────────┘
                                     ↑ 每步输出作为下步输入
```

**核心思想：**

1. **编码器**：用LSTM读完整个源句子，压缩为一个**固定长度的向量**（"编码向量"）
2. **解码器**：用这个向量初始化另一个LSTM，逐步生成目标句子

**数学本质——条件语言模型：**

- 普通LM：P(y₁, y₂, ..., yₜ)
- 条件LM：P(y₁, y₂, ..., yₜ | x₁, x₂, ..., xₛ)
- 解码器 = 一个以编码器输出为条件的普通语言模型

> 💡 **类比：** 编码器是一个读完一本法语书的翻译官。他把所有内容概括成一段话（编码向量），然后交给另一个翻译官（解码器），让他根据这段话写出英文版本。

### 2.2 训练 vs 测试的关键区别

| 阶段             | 解码器输入         | 效果        |
| ---------------- | ------------------ | ----------- |
| 训练（教师强制） | 真实的上一个词     | 快速收敛    |
| 测试（自回归）   | 自己生成的上一个词 | 错误累积 ⚠️ |

> ⚠️ **暴露偏差（Exposure Bias）：** 训练时解码器总是收到正确答案，但测试时必须用自己的（可能错误的）预测。如果第一个词就翻错了，后面可能全部偏离。

### 2.3 ❌ 致命缺陷——信息瓶颈

将整个源句子（可能50+个词）压缩为一个固定大小的向量（如512维），必然丢失信息。

```
源句子: "The old man who lived in the small house on the hill
         with the red roof and the beautiful garden went to
         the market to buy some fresh vegetables and fruits."

                    ↓ 压缩为 ↓

编码向量: [0.23, -0.87, 0.44, ..., 0.12]  (仅512个数字)

                    ↓ 解码器必须从这个向量重建整个句子
```

> 💡 **传话游戏类比：** A读了一本书，只能对B说**一句话**。B必须从这一句话重建整本书。书越长，丢失的细节越多。

**实验证据：** Seq2Seq在短句子（<20词）上表现不错，但在长句子上翻译质量急剧下降——因为编码向量记不住那么多信息。

|   维度   |       Bi-LSTM       |       Seq2Seq        |
| :------: | :-----------------: | :------------------: |
| 方向盲区 |       ✅ 解决       | ✅ 编码器可用Bi-LSTM |
| 长度不同 |      ❌ 不支持      |       ✅ 解决        |
| 信息保留 | ✅ 每步都有隐藏状态 |  ❌ 压缩为单一向量   |

> 🔑 **故事转折点：** Seq2Seq解决了"输入输出长度不同"的问题，但引入了信息瓶颈——整个句子被塞进一个向量。翻译长句子时细节丢失。我们需要让解码器在**每一步**都能回头看源句子的**任何位置** → **注意力机制**登场！

## 🎯 第三章：注意力机制——让解码器"回头看"（✅ 解决信息瓶颈，⚠️ 新问题出现）

### 3.1 核心思想

**不再只给解码器一个固定向量，而是让它在每一步都能"看到"所有编码器隐藏状态。**

```
传统Seq2Seq（无注意力）：
  编码器 ──[一个向量]──→ 解码器（所有步共用同一个向量）

有注意力的Seq2Seq：
  编码器 ──[所有隐藏状态]──→ 解码器（每步动态选择关注哪些状态）
```

### 3.2 注意力的计算步骤

翻译 "il a m' entarté" → "he hit me with a pie"，当解码器在生成 "pie" 时：

```
步骤1: 计算相似度
  attention_score[i] = dot(decoder_state, encoder_state[i])

  结果: [0.1, 0.05, 0.02, 0.83]
         "il"  "a"  "m'"  "entarté"
                              ↑ 最相关！

步骤2: Softmax → 概率分布
  attention_weights = softmax([0.1, 0.05, 0.02, 0.83])
                    ≈ [0.10, 0.09, 0.09, 0.72]

步骤3: 加权求和 → 上下文向量
  context = 0.10×h₁ + 0.09×h₂ + 0.09×h₃ + 0.72×h₄
  → 主要包含 "entarté" 的信息

步骤4: 拼接 + 输出
  [decoder_state ; context] → 输出层 → "pie"
```

> 💡 **聚光灯类比：** 源句子是一个舞台，每个词是一个演员。无注意力时，解码器通过一个**小窥视孔**看舞台（只能看到模糊的整体）。有注意力时，解码器有一个**聚光灯**，可以随时对准任何演员。翻译 "pie" 时聚光灯照 "entarté"，翻译 "he" 时聚光灯移到 "il"。

### 3.3 注意力的四大优势

1. **消除瓶颈：** 信息不再需要压缩为一个向量
2. **处理长句子：** 每个词都可以直接被访问，无论多远
3. **可解释性：** 注意力权重 = 对齐表（可以可视化哪个源词对应哪个目标词）
4. **梯度直通：** 提供从编码器到解码器的**快捷路径**，缓解梯度消失

### 3.4 ❌ 注意力的代价与限制

**每步需要看所有编码器状态：O(n) per step，总计 O(m×n)**

|   维度   |   无注意力   |       有注意力       |
| :------: | :----------: | :------------------: |
|  上下文  | 单一固定向量 |   每步动态加权 ✅    |
|  长句子  |   严重退化   |       良好 ✅        |
| 可解释性 |     黑盒     |   注意力可视化 ✅    |
| 计算成本 |   O(1)/步    |      O(n)/步 ⚠️      |
| 顺序依赖 | RNN顺序处理  | 仍然是RNN顺序处理 ❌ |

> 🔑 **关键遗留问题：** 注意力解决了信息瓶颈，但编码器和解码器**仍然是RNN/LSTM**。这意味着token必须**顺序处理**（token 5 等 token 1-4）。在GPU时代，这种顺序处理是巨大的效率浪费——GPU擅长的是**并行计算**。

> 🔑 **故事转折点：** 注意力证明了"直接看相关位置"比"压缩所有信息"更好。那如果我们把这个思想推到极致——**完全不用RNN**，让每个词直接注意到每个其他词呢？→ **Transformer**登场！

## ⚡ 第四章：Transformer——"Attention Is All You Need"（✅ 解决顺序处理，🚀 开启新时代）

### 4.1 核心突破：抛弃循环，拥抱并行

```
RNN/LSTM的处理方式（顺序）：
  词₁ → 词₂ → 词₃ → 词₄ → 词₅    (5步，不能并行)

Transformer的处理方式（并行）：
  词₁  词₂  词₃  词₄  词₅          (1步，全部并行)
   ↕    ↕    ↕    ↕    ↕
  自注意力：每个词同时看到所有其他词
```

**Transformer的关键创新：**

| 组件     | RNN时代           | Transformer                 |
| -------- | ----------------- | --------------------------- |
| 序列处理 | 循环（顺序）      | 自注意力（并行）            |
| 位置信息 | 隐式（处理顺序）  | 显式（位置编码）            |
| 编码器   | RNN/LSTM          | 自注意力 + FFN 堆叠         |
| 解码器   | RNN/LSTM + 注意力 | 自注意力 + 交叉注意力 + FFN |

### 4.2 自注意力 vs RNN注意力

| 维度       | RNN注意力（本讲） | 自注意力（Transformer） |
| ---------- | :---------------: | :---------------------: |
| 谁看谁？   |  解码器看编码器   |   每个词看每个其他词    |
| 依赖RNN？  |       ✅ 是       |          ❌ 否          |
| 并行？     |      ❌ 不能      |       ✅ 完全并行       |
| 长距离依赖 |  通过注意力改善   |  **O(1) 路径长度** ✅   |

> 💡 **类比：** RNN注意力 = 翻译官查阅原文（解码器→编码器）。自注意力 = 一屋子人同时互相交流（每个词→每个词）。"The cat sat on the mat because **it** was tired" 中的 "it" 可以直接看到 "cat"，无论距离多远。

### 4.3 Transformer的历史意义

2017年 "Attention Is All You Need" 之后的爆发：

- **BERT**（2018）：仅编码器，双向自注意力 → 理解任务之王
- **GPT**（2018-2024）：仅解码器，自回归自注意力 → 生成任务之王
- **T5**（2019）：编码器-解码器，统一文本到文本 → 万能转换器

> 🔑 **Transformer不仅仅是一个更好的翻译模型——它是整个现代AI的基础架构。ChatGPT、Claude、Gemini，全部建立在Transformer之上。**

```
┌────────────────────────────────────────────────────────────┐
│               NLP序列处理技术演进路线图                        │
│                                                            │
│  单向 LSTM                                                 │
│    ✅ 记住长距离信息（门控机制）                              │

│              │                                             │
│              ▼                                             │

│    ✅ 同时看左右两侧 → 完整上下文表示                        │

│              │                                             │
│              ▼                                             │

│    ✅ 两阶段：先理解(编码)再生成(解码)                       │

│    ✅ 解码器每步动态关注源句的不同部分                        │

│    ❌ 仍基于RNN，顺序处理，无法并行                          │
│              │                                             │

│  Transformer ("Attention Is All You Need")                 │
│    ✅ 自注意力：完全抛弃循环，全部并行                        │
│    ✅ O(1)路径长度：任何两个位置直接连接                      │
│    🚀 催生GPT、BERT、所有现代LLM                            │
│              │                                             │
│              ▼                                             │
│  下一站：BERT？GPT？预训练+微调范式？                        │
└────────────────────────────────────────────────────────────┘
```

### 转折总结表

| 从 → 到                     | 解决了什么核心问题？                  | 代价是什么？               |
| --------------------------- | ------------------------------------- | -------------------------- |
| 单向LSTM → Bi-LSTM          | 方向盲区：只看左边 → 看两边           | 不能生成；参数翻倍         |
| Bi-LSTM → Seq2Seq           | 长度不同：输入5词 → 输出8词           | 信息瓶颈（一个向量装不下） |
| Seq2Seq → +Attention        | 信息瓶颈：一个向量 → 动态加权所有位置 | 仍需顺序处理（RNN）        |
| RNN+Attention → Transformer | 顺序处理：O(n)步 → O(1)步并行         | O(n²)内存；需要位置编码    |

### 一句话总结演进动力

> **每一步创新都在回答同一个问题的不同层面：**
>
> - Bi-LSTM："怎么看到更多上下文？" → 往两边看
> - Seq2Seq："怎么从读到写？" → 分成两个阶段
> - Attention："怎么记住所有细节？" → 每步回头看
> - Transformer："怎么更快地做到以上所有？" → 全部并行
