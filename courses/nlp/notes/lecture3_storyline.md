# Lecture 3 故事线：从"词是符号"到"词有权重"——频率方法的四连升级

> **Source:** `lecture_3_W26.pdf` (48 pages)
> **核心主题：** 机器不认识文字，只认识数字。怎么把文本变成数字向量，让机器能计算"两段文字有多像"？
> **故事线：** 一场"文本数字化"的进化之旅——每种方法都在修补上一种的致命缺陷，从最笨的二进制编码到最聪明的重要性加权

---

## 🎬 序幕：机器的根本困境——它不认字

### 一句话概括

> 机器学习模型只能处理数字。但我们给它的是文字。怎么把 "I love NLP" 变成 `[0.3, 0.7, 0.1, ...]` 这样的数字向量？

**核心矛盾：**

```
人类看到的：  "I love NLP"
机器需要的：  [0.33, 0.33, 0, 0.33]  ← 某种数值向量
```

从左边到右边，就是本讲要解决的问题：**文本向量化（Text Vectorization）**。

### 为什么这很重要？

> **表示方式决定模型天花板。** 一个用好的表示方法搭配简单模型，往往胜过用差的表示方法搭配最先进模型。

| 场景 | 没有好的向量化会怎样 |
|------|-------------------|
| **文本分类** | 模型无法区分"体育新闻"和"科技新闻" |
| **搜索引擎** | 搜 "happy" 找不到含 "joyful" 的文档 |
| **抄袭检测** | 无法计算两篇论文的相似度 |
| **推荐系统** | 无法判断用户喜欢的内容类型 |

### 本讲的故事线

```
📖 故事脉络：

向量空间模型（理论基础）
→ One-Hot Encoding（最笨：只有0和1）
  ❌ 无频率、无语义、极度稀疏
→ Bag of Words（升级1：有频率了）
  ❌ 丢失词序、常见词主导
→ N-Gram（升级2：部分恢复词序）
  ❌ 特征爆炸、仍无语义
→ TF-IDF（升级3：有重要性权重了）
  ❌ 仍无语义理解
→ 相似度度量（如何比较两个向量？）
  余弦相似度、欧几里得距离、编辑距离
```

### 全景图：四种方法的进化链

```
┌─────────────────────────────────────────────────────────┐
│           文本向量化方法 进化路线图                        │
│                                                         │
│  📌 One-Hot Encoding（独热编码）                          │

│    ✅ 简单直观                                           │
│    ❌ 无频率、无语义、极度稀疏                             │
│              │                                          │
│              ▼ "能不能记录词出现了几次？"                  │
│                                                         │
│  📊 Bag of Words（词袋模型）                              │
│    "cat dog cat" → [2, 1]  (cat=2, dog=1)               │
│    ✅ 有频率信息了                                        │
│    ❌ 丢失词序、"the"出现100次主导一切                     │

│    "quantum" → 高权重（很稀有）                           │

```

> 💡 **关键洞察：** 这四种方法都是**频率方法**——它们只关心"词出现了几次"，完全不理解"词是什么意思"。理解语义需要**词嵌入**（Word2Vec、GloVe），那是 Week 4 的内容。

## 📐 第一章：向量空间模型——一切的数学基础

> **对应 Slides:** Page 3-9
> **为什么先讲这个？** 所有文本向量化方法的底层逻辑都是同一个：把文本映射到一个数学空间，然后用几何运算（距离、角度）来衡量相似度。先理解这个"空间"，后面的方法才有根基。

### 1.1 核心思想

> **向量空间模型（Vector Space Model）= 把文本变成空间中的点，然后用"距离"衡量相似度。**

想象一个坐标系：
- 每个维度代表词表中的一个词
- 每个文档是这个空间中的一个点
- 两个点越近，两个文档越相似

### 1.2 两个关键数学工具

**① L₂ 范数（向量长度）**

```
‖x‖ = √(x₁² + x₂² + ... + xₙ²)
```

> 就是勾股定理的 n 维推广。衡量向量"有多长"。

**② 点积（内积）**

```
x · y = x₁y₁ + x₂y₂ + ... + xₙyₙ
```

> 衡量"两个向量指向同一方向的程度"。点积大 = 方向接近 = 内容相似。

这两个工具组合起来就是**余弦相似度**（第七章会详细讲）：

```
cos(θ) = (x · y) / (‖x‖ × ‖y‖)
```

### 1.3 基本术语

| 术语 | 定义 | 类比 |
|------|------|------|
| **向量化 (Vectorizing)** | 把文本编码为数值向量的过程 | 给文本分配 GPS 坐标 |
| **特征向量 (Feature Vector)** | 表示一个文本的 n 维数值向量 | 文本在空间中的坐标 |
| **文档-词项矩阵 (DTM)** | 行=文档，列=词，值=某种数值 | 一张大表格 |

> 💡 **地图类比：** 向量空间模型就像给每个文档分配 GPS 坐标。含义相似的文档坐标接近（"happy" 靠近 "joyful"），不相关的文档坐标遥远（"happy" 远离 "database"）。

> 🔑 **故事转折点：** 理论框架有了，但具体怎么把文本变成向量？最简单的方法：给每个词一个独一无二的二进制编码。

## 💡 第二章：One-Hot Encoding——最笨但最直觉的方法（❌ 全面失败）

> **对应 Slides:** Page 10-12
> **核心思想：** 每个词用一个二进制向量表示，只有自己的位置是 1，其余全是 0。

### 2.1 一句话定义

> **One-Hot Encoding = 给每个词一个专属的灯光开关。** 10,000 个词 = 10,000 个开关，每次只亮一个。

### 2.2 具体例子

```
词表: {I, love, NLP}  （3个词 → 3维空间）

I    = [1, 0, 0]
love = [0, 1, 0]
NLP  = [0, 0, 1]
```

对于文档级别，可以构建一个词表×文档的矩阵，每行是一个词的独热向量。

### 2.3 ❌ 三大致命问题

| 问题 | 说明 | 后果 |
|------|------|------|
| **极度稀疏** | 50,000 词的词表 → 50,000 维向量，只有 1 个非零值 | 99.998% 的空间被浪费 |
| **无频率信息** | "the" 出现 100 次和 1 次，编码完全相同 | 无法区分重要词和普通词 |
| **无语义关系** | "happy" 和 "glad" 的距离 = "happy" 和 "volcano" 的距离 | 同义词被当成完全不同的词 |

> 💡 **灯光开关类比：** 想象一个有 10,000 个灯光开关的房间。每个词只亮一个开关，其余 9,999 个全灭。这极其浪费——而且 "happy" 的开关和 "glad" 的开关之间没有任何物理联系。

### 2.4 OHE 的唯一用途

OHE 虽然作为文本表示很差，但在机器学习中用于编码**分类变量**（如颜色、国家）时仍然有用——因为分类变量之间确实没有"距离"概念。

> 🔑 **故事转折点：** OHE 连"一个词出现了几次"都记不住。我们至少需要一个能记录频率的方法 → **词袋模型**登场。

## 📊 第三章：Bag of Words——终于有频率了（⚠️ 但丢了词序）

> **对应 Slides:** Page 13-18
> **核心思想：** 把文档中所有词倒进一个"袋子"，只数每个词出现了几次，完全忽略顺序。

### 3.1 一句话定义

> **BOW = 把文档当成一个购物袋，只关心袋子里有什么、每种有几个，不关心放进去的顺序。**

### 3.2 具体例子

```
文档: "cat dog cat bird dog dog"
词表: {bird, cat, dog}

BOW 向量: [1, 2, 3]
           ↑  ↑  ↑
         bird cat dog
         1次  2次 3次
```

**Python 实现：**

```python
from sklearn.feature_extraction.text import CountVectorizer

corpus = ['This is the first document.',
          'This is the second document.',
          'And the third one.']
cv = CountVectorizer()
X = cv.fit_transform(corpus)
# 输出：文档-词项矩阵（DTM），行=文档，列=词，值=出现次数
```

### 3.3 ✅ 相比 OHE 的进步

| 维度 | OHE | BOW |
|------|:---:|:---:|
| 表示粒度 | 每个词一个向量 | 每个文档一个向量 |
| 频率信息 | ❌ 只有 0/1 | ✅ 记录出现次数 |
| 文档比较 | 无法直接比较 | ✅ 可以计算文档相似度 |

### 3.4 ❌ BOW 的致命问题

**问题 1：词序完全丢失**

```
"John is quicker than Mary"  → {John:1, is:1, quicker:1, than:1, Mary:1}
"Mary is quicker than John"  → {John:1, is:1, quicker:1, than:1, Mary:1}

两个向量完全相同！但含义完全相反！
```

**问题 2：常见词主导**

"the" 在每个文档中出现 10+ 次，主导了向量值。但 "the" 对区分文档毫无帮助——它在每个文档中都出现。

**问题 3：仍然无语义**

"happy" 和 "glad" 仍然是两个完全独立的维度，没有任何关联。

> 💡 **购物袋类比：** BOW 就像把超市购物清单上的东西全倒进袋子里摇一摇。你知道袋子里有 3 个苹果和 2 瓶牛奶，但你不知道苹果是先放的还是后放的。"Dog bites man" 和 "Man bites dog" 变成了同一个袋子。

> 🔑 **故事转折点：** 词序丢失是致命的——"not good" 变成了 {not:1, good:1}，否定消失了。能不能至少保留一点词序？→ **N-Gram** 登场。

## 📎 第四章：N-Gram——用词对恢复部分词序（⚠️ 但特征爆炸了）

> **对应 Slides:** Page 19-21
> **核心思想：** 不只看单个词，还看连续的 2 个词（bigram）、3 个词（trigram）作为特征。

### 4.1 一句话定义

> **N-Gram = 把连续 N 个词当作一个整体特征。** Bigram 保留了相邻词的顺序，部分修复了 BOW 的词序盲。

### 4.2 三种粒度

以 "I am learning NLP" 为例：

| 类型 | N | 结果 |
|------|---|------|
| Unigram | 1 | "I", "am", "learning", "NLP" |
| Bigram | 2 | "I am", "am learning", "learning NLP" |
| Trigram | 3 | "I am learning", "am learning NLP" |

### 4.3 ✅ 关键改进：保留否定

BOW 的致命伤——"not good" 被拆成 {not:1, good:1}——在 bigram 中被修复：

```
BOW:    "not good" → {not:1, good:1}     ← 否定消失，看起来是正面的
Bigram: "not good" → {"not good":1}       ← 否定保留，作为一个整体特征
```

这对情感分析至关重要。

### 4.4 ❌ N-Gram 的致命问题：特征爆炸

| 词表大小 V | Unigram 特征数 | Bigram 特征数 | Trigram 特征数 |
|:---:|:---:|:---:|:---:|
| 10,000 | 10,000 | 10,000² = 1亿 | 10,000³ = 1万亿 |

> 大部分 bigram/trigram 组合在实际文本中从不出现（极度稀疏），但计算成本已经爆炸了。

**实践建议：** N > 3 几乎不用。最常用的是 unigram + bigram 组合：

```python
from sklearn.feature_extraction.text import CountVectorizer
cv = CountVectorizer(ngram_range=(1, 2))  # unigram + bigram
```

### 4.5 N-Gram 仍未解决的问题

- ❌ 仍然无语义（"happy" 和 "glad" 仍然无关）
- ❌ 仍然无法区分重要词和垃圾词（"the is" 这个 bigram 毫无价值但会被记录）
- ❌ OOV 问题（没见过的词/词对无法表示）

> 💡 **乐高类比：** Unigram 是单个乐高积木——你知道颜色但不知道形状。Bigram 是拍摄每对相连积木的照片——你开始看到边缘和连接。Trigram 展示更多结构，但照片数量爆炸式增长。

> 🔑 **故事转折点：** N-Gram 部分恢复了词序，但还有一个大问题没解决——"the" 出现 100 次，"quantum" 出现 1 次，BOW 和 N-Gram 都给 "the" 更高的值。但 "the" 毫无区分能力，"quantum" 才是关键词。能不能自动识别哪些词重要？→ **TF-IDF** 登场。

## ⚖️ 第五章：TF-IDF——用稀有度衡量重要性（✅ 频率方法的巅峰）

> **对应 Slides:** Page 22-34
> **核心思想：** 一个词的重要性 = 它在本文档中出现的频率 × 它在整个语料库中的稀有程度。常见词降权，稀有词升权。

### 5.1 一句话定义

> **TF-IDF = 侦探思维。** 每篇文章都有 "the" 和 "is"——这些是无用线索。但只有这篇文章有 "earthquake"——这才是破案关键。TF-IDF 自动忽略常见词，聚焦稀有词。

### 5.2 公式拆解

**TF-IDF = TF × IDF**

**① TF（词频）——这个词在本文档中有多频繁？**

```
TF(词, 文档) = 词在文档中出现次数 / 文档总词数
```

> 为什么要除以总词数？因为一个词在 100 词的文档中出现 5 次，比在 10,000 词的文档中出现 5 次更重要。归一化消除文档长度的影响。

**② IDF（逆文档频率）——这个词在整个语料库中有多稀有？**

```
IDF(词) = log(总文档数 N / 包含该词的文档数 df)
```

> - 如果一个词出现在每个文档中：IDF = log(N/N) = log(1) = 0 → 权重为零（"the"）
> - 如果一个词只出现在 1 个文档中：IDF = log(N/1) = log(N) → 权重最高（"quantum"）

**③ 为什么需要 log？**

没有 log，一个在 1,000,000 文档中只出现 1 次的词会得到 IDF = 1,000,000——数值爆炸。log 把它压缩到 6（log₁₀(1,000,000) = 6），保持数值在合理范围。

### 5.3 完整计算示例

**语料库：**
- D1: "Dog bites man"
- D2: "Man bites dog"
- D3: "Dog eats meat"
- D4: "Man eats food"

**计算 D1 中 "dog" 的 TF-IDF：**

```
Step 1: TF("dog", D1) = 1/3 ≈ 0.333  （D1 有 3 个词，"dog" 出现 1 次）
Step 2: IDF("dog") = log(4/3) ≈ 0.125  （4 个文档中 3 个含 "dog"）
Step 3: TF-IDF = 0.333 × 0.125 ≈ 0.042  （"dog" 太常见，权重低）
```

**对比 "food" 在 D4 中的 TF-IDF：**

```
TF("food", D4) = 1/3 ≈ 0.333
IDF("food") = log(4/1) ≈ 0.602  （只有 D4 含 "food"，很稀有！）
TF-IDF = 0.333 × 0.602 ≈ 0.201  （"food" 稀有，权重高）
```

> "food" 的 TF-IDF 是 "dog" 的近 5 倍——因为 "food" 更能区分 D4 和其他文档。

### 5.4 TF-IDF 的威力：实战对比

**场景：** 5 个文档都含 "hot"，但语境不同：

```
D1: "The weather is hot under the sun"
D2: "I make my hot chocolate with milk"
D3: "One hot encoding"
D4: "I will have a chai latte with milk"
D5: "There is a hot sale today"
```

**CountVectorizer 的结果：** D1 和 D3 最相似（0.408）——因为都有 "hot"。但这是误导！"hot" 太常见了。

**TF-IDF 的结果：** D2 和 D4 最相似（0.232）——因为都有 "milk"。"milk" 只出现在 2 个文档中，是更好的区分词。

> TF-IDF 自动发现了 "milk" 比 "hot" 更有区分力——不需要人工干预。

### 5.5 Python 实现

```python
from sklearn.feature_extraction.text import TfidfVectorizer

corpus = ['The weather is hot under the sun',
          'I make my hot chocolate with milk',
          'One hot encoding',
          'I will have a chai latte with milk',
          'There is a hot sale today']

tfidf = TfidfVectorizer()
X = tfidf.fit_transform(corpus)
# "hot" 权重低（出现在 4/5 文档中）
# "milk" 权重高（只出现在 2/5 文档中）
```

### 5.6 ❌ TF-IDF 仍未解决的问题

| 问题 | 说明 |
|------|------|
| **无语义理解** | "happy" 和 "joyful" 仍然是两个独立维度，没有关联 |
| **稀疏** | 词表 50,000 → 向量 50,000 维，大部分为 0 |
| **小语料库效果差** | 只有 5 个文档时，IDF 的统计意义很弱 |
| **OOV** | 没见过的词无法表示 |

> 💡 **报纸侦探类比：** TF-IDF 就像一个侦探在读报纸。"the" 和 "is" 出现在每篇文章中——无用线索，忽略。但 "earthquake" 只出现在一篇文章中——关键线索，重点关注。侦探（TF-IDF）自动聚焦于最有区分力的词。

> 🔑 **故事转折点：** TF-IDF 是频率方法的巅峰——它能自动识别重要词。但它的根本局限是**不理解语义**。"happy" 和 "joyful" 在 TF-IDF 眼中毫无关系。要突破这个瓶颈，需要一种全新的思路——让词的"含义"也变成向量 → **词嵌入**（Week 4）。

> 但在进入 Week 4 之前，还有一个问题：我们已经把文本变成了向量，怎么衡量两个向量"有多像"？

## 📏 第六章：相似度度量——如何比较两个向量？

> **对应 Slides:** Page 35-45
> **为什么需要这章？** 前五章解决了"怎么把文本变成向量"。但变成向量之后呢？我们需要一种方法来回答："这两个文档有多像？"

### 6.1 五种相似度度量一览

| 度量 | 衡量什么 | 适用场景 |
|------|---------|---------|
| **余弦相似度** | 向量夹角 | 文档相似度（最常用） |
| **欧几里得距离** | 直线距离 | 聚类 |
| **Levenshtein 距离** | 编辑操作次数 | 拼写纠错 |
| **Jaccard 相似度** | 集合交集/并集 | 集合比较 |
| **汉明距离** | 不同位的数量 | 二进制比较 |

### 6.2 余弦相似度（Cosine Similarity）——最重要的度量

> **余弦相似度 = 两个向量之间夹角的余弦值。** 不关心向量长度，只关心方向。

**公式：**

```
cos(θ) = (A · B) / (‖A‖ × ‖B‖)

其中：
  A · B = 点积 = Σ(aᵢ × bᵢ)
  ‖A‖  = L₂范数 = √(Σaᵢ²)
```

**值域：**
- cos = 1 → 完全相同方向（最相似）
- cos = 0 → 正交（完全无关）
- cos = -1 → 完全相反方向

**计算示例：**

```
Doc1 = "I love NLP"  → [1, 1, 0, 1]  (I=1, love=1, you=0, NLP=1)
Doc2 = "I love you"  → [1, 1, 1, 0]  (I=1, love=1, you=1, NLP=0)

点积:  1×1 + 1×1 + 0×1 + 1×0 = 2
‖Doc1‖ = √(1+1+0+1) = √3
‖Doc2‖ = √(1+1+1+0) = √3

cos(θ) = 2 / (√3 × √3) = 2/3 ≈ 0.667
```

> 两个文档共享 "I" 和 "love"，相似度 0.667——合理。

### 6.3 为什么余弦比欧几里得更适合文本？

| 场景 | 欧几里得距离 | 余弦相似度 |
|------|:-:|:-:|
| 短文档 vs 长文档（内容相同但长度不同） | ❌ 距离大（因为长文档向量值更大） | ✅ 相似度高（方向相同） |
| 两个主题相同的文档 | 受长度影响 | 只看方向，不受长度影响 |

> 💡 **指南针类比：** 余弦相似度就像比较两个指南针的方向。不管指南针大小（文档长度），只要指向同一方向（相同主题），就是相似的。欧几里得距离则像比较两个指南针的物理距离——大指南针和小指南针即使指向相同方向，距离也很远。

### 6.4 Levenshtein 距离（编辑距离）——字符级别的相似度

> **Levenshtein 距离 = 把一个词变成另一个词最少需要几步操作？**

三种操作：
- **插入**一个字符
- **删除**一个字符
- **替换**一个字符

**经典例子：kitten → sitting**

```
kitten → sitten  （替换 k→s）     操作 1
sitten → sittin  （替换 e→i）     操作 2
sittin → sitting （插入 g）       操作 3

Levenshtein 距离 = 3
```

**应用场景：** 拼写纠错（"teh" → "the"，距离=1）、DNA 序列比对、模糊搜索。

> 💡 注意：Levenshtein 距离是**字符级别**的，而余弦相似度是**文档/向量级别**的。它们解决不同层面的问题。

### 6.5 欧几里得距离

```
d(A, B) = √(Σ(aᵢ - bᵢ)²)
```

就是两点之间的直线距离。简单直观，但对文本来说不如余弦——因为它受向量长度（文档长度）影响。

### 6.6 实战对比：CountVectorizer vs TF-IDF 的相似度结果

回到第五章的 "hot" 例子：

| 方法 | 最相似的文档对 | 原因 |
|------|--------------|------|
| CountVectorizer + 余弦 | D1 & D3（0.408） | 都有 "hot"——但 "hot" 太常见，这是误导 |
| TF-IDF + 余弦 | D2 & D4（0.232） | 都有 "milk"——稀有词，真正的区分信号 |

> 这个对比完美展示了 TF-IDF 的价值：同样用余弦相似度，但 TF-IDF 的加权让结果更合理。

## 🗺️ 全局回顾：频率方法技术演进路线图

### 四种方法的终极对比

| 维度 | OHE | BOW | N-Gram | TF-IDF |
|------|:---:|:---:|:------:|:------:|
| 值类型 | 0/1 二进制 | 整数计数 | 整数计数 | 加权浮点数 |
| 频率信息 | ❌ | ✅ | ✅ | ✅（加权） |
| 词序信息 | ❌ | ❌ | ⚠️ 部分（N窗口内） | ❌ |
| 重要性区分 | ❌ | ❌ | ❌ | ✅ |
| 语义理解 | ❌ | ❌ | ❌ | ❌ |
| 稀疏性 | 极度稀疏 | 稀疏 | 更稀疏 | 稀疏 |
| OOV 处理 | ❌ | ❌ | ❌ | ❌ |
| 典型用途 | 分类变量编码 | 文本分类 | 情感分析 | 信息检索、搜索 |

### 每次升级解决了什么？

| 从 → 到 | 解决了什么核心问题？ | 引入了什么新问题？ |
|----------|-------------------|-------------------|
| OHE → BOW | 从"有没有"升级到"有几个"（频率） | 词序完全丢失 |
| BOW → N-Gram | 部分恢复词序（"not good" 保留否定） | 特征数量指数爆炸 |
| N-Gram → TF-IDF | 自动区分重要词和垃圾词 | 仍无语义理解 |
| TF-IDF → 词嵌入 (Week 4) | 理解词的含义（happy ≈ glad） | 需要大量数据训练 |

### 三种相似度度量对比

| 度量 | 层级 | 公式 | 最佳场景 |
|------|------|------|---------|
| 余弦相似度 | 文档级 | cos(θ) = (A·B)/(‖A‖‖B‖) | 文档比较（不受长度影响） |
| 欧几里得距离 | 文档级 | √(Σ(aᵢ-bᵢ)²) | 聚类（受长度影响） |
| Levenshtein | 字符级 | 最少编辑操作数 | 拼写纠错、模糊匹配 |
