前面几讲我们学了 CNN 的架构和训练原理，从卷积层到反向传播，理论上都清楚了。
但真要动手实现一个能跑的图像分类器，你会发现一个残酷的现实。
手写梯度计算太痛苦，数据加载效率太低，GPU 加速要自己管理。
我们需要一个专门的深度学习框架来解放双手。
这个框架就是 PyTorch。

为什么是 PyTorch 而不是别的框架呢？
先看一段历史。
2002 年，Torch 诞生了，用的是 Lua 语言，是第一个支持 GPU 加速的机器学习框架。
但 Lua 的生态太小，Python 拥有 NumPy、Pandas、Matplotlib 这些海量科学计算库。
所以 2016 年，Facebook 的 FAIR 实验室发布了 PyTorch，把 Torch 的 GPU 加速能力包装在 Python 里。
2022 年 PyTorch 转入 Linux Foundation 开放治理，不再是 Meta 独占。
2023 年 PyTorch 2.0 发布，torch.compile 大幅提升了运行速度。

理解 PyTorch 和 TensorFlow 的差异，关键在于静态图和动态图之分。
TensorFlow 用的是 Define-and-Run 模式，先定义完整的计算图再喂数据，调试很不方便。
PyTorch 用的是 Define-by-Run 模式，边写边执行，每次前向传播即时构建图。
PyTorch 可以直接用 print 和 pdb 调试，像写普通 Python 一样搭网络。
一句话总结就是，做研究和学习选 PyTorch，灵活直观调试方便。
做生产部署选 TensorFlow，工具链更成熟，但差距正在缩小。

弄清楚了为什么选 PyTorch，我们来看它内部是怎么工作的。
PyTorch 有三大核心组件，我们逐一拆解。

第一个核心组件是 Tensor 张量。
张量就是支持 GPU 加速的多维数组，可以理解为 NumPy 的 ndarray 加上 CUDA 能力。
从标量到向量到矩阵再到高阶张量，维度逐步推广。
0 维是标量，比如一个温度值 36.5。
1 维是向量，比如一个 RGB 颜色值。
2 维是矩阵，比如一张 28 乘以 28 的灰度图。
3 维是彩色图，通道数乘以高度乘以宽度。
4 维是一批图片，在 PyTorch 中形状永远是 Batch 乘以 Channel 乘以 Height 乘以 Width。

张量有三大超能力。
第一，GPU 加速，一行代码把运算搬到显卡。
第二，支持分布式处理，多 GPU 多服务器并行计算。
第三，计算图追踪，每个张量记住谁创建了它，这是自动微分的基础。

张量能追踪计算图，但谁来利用这个计算图自动求导呢？
这就引出了第二个核心组件，Autograd 自动求导引擎。

训练神经网络的核心是梯度下降，参数新等于参数旧减去学习率乘以偏导数。
现代神经网络有数百万个参数，手写每个参数的偏导数根本不可能。
PyTorch 的解决方案是反向自动微分。
前向传播时正常运行网络，同时悄悄记录所有运算到计算图。
计算损失之后，调用 loss.backward，PyTorch 沿着计算图反向逐步求导。
优化器再利用计算出的梯度更新参数。
Autograd 就像倒带功能，前向传播是录像，backward 是倒放录像，沿着路径计算每一步的影响。

要参与梯度计算的张量需要设置 requires_grad 为 True。
backward 之后，每个参数的 grad 属性就存好了梯度。
Autograd 解放了研究者，你只需定义前向传播，反向传播全自动。

有了数据容器和求导引擎，还缺什么呢？
需要一种组织网络结构的方式，这就是第三个核心组件 nn.Module。
nn.Module 是 PyTorch 中所有网络的基类，提供了统一的搭积木接口。
设计哲学是，init 方法里列清单，定义有哪些层。
forward 方法里画路线，定义数据怎么流。
就像一个工厂蓝图，先买好所有机器，再规定产品的流转路线。

接下来看损失函数和优化器在 PyTorch 中的选择。
分类任务用 CrossEntropyLoss，衡量预测的概率分布和真实标签差多远。
回归任务用 MSELoss，计算预测值和真实值的均方误差。
优化器方面，SGD 最基础需要手动调学习率。
Adam 是自适应学习率，收敛快，是大多数场景的默认选择。
RMSprop 自适应且擅长处理稀疏梯度，适合 RNN 和 NLP。

掌握了三大组件，我们来看训练的完整流程，分为三大阶段。
第一阶段是数据准备，用 Dataset 定义数据从哪来怎么读，用 DataLoader 定义数据怎么送进模型。
DataLoader 自动批量化、打乱顺序、多进程加载。
就像 Dataset 是菜市场，定义了每种菜在哪、怎么挑。
DataLoader 是外卖小哥，自动打包配送，还能并行送多单。

第二阶段是模型开发，定义网络、选择损失函数、选择优化器，然后执行训练循环和验证循环。
第三阶段是模型部署，用 torch.save 保存模型，用 TorchScript 导出，部署到云端或边缘设备。

讲完了核心组件和训练流程，我们来看 CV 实战中最重要的工具。
PyTorch 为计算机视觉专门提供了 torchvision 库。
torchvision.models 包含预训练模型，比如 ResNet、VGG、EfficientNet。
torchvision.datasets 包含标准数据集，比如 ImageNet、CIFAR-10。
torchvision.transforms 包含图像变换操作，用于裁剪、归一化和数据增强。

Transfer Learning 迁移学习的核心思想是，不从零训练，而是借用在 ImageNet 上预训练好的模型。
只替换最后的分类层，用自己的数据微调。
为什么迁移学习有效呢？
预训练模型的前几层学到的是通用视觉特征，比如边缘、纹理、形状。
这些特征在不同 CV 任务间是共享的，只需微调后几层就能适配新任务。

最后简要了解几个生产级特性。
CUDA 支持让计算搬到 GPU，分布式训练解决单 GPU 内存不够的问题。
JIT 编译器，也就是 TorchScript，将模型编译为优化的中间表示，运行更快。
C++ 前端可以脱离 Python 解释器部署。

最佳实践方面要记住几点。
尽可能使用 GPU，正确划分数据集，用 DataLoader 管理数据。
定期保存模型，代码模块化，记录超参数和实验结果。
