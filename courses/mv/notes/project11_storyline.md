# CST8508 期末项目故事线：从「看到人」到「追着人走」

> **Source:** `CST8508_Project11.docx`
> **核心主题：** 如何让摄像头自动跟住画面中的人，并把他/她移到正中间？
> **故事线：** 从裸视频流出发，一步步叠加「检测 → 追踪 → 居中控制」三层能力，像给机器装上了眼睛（Detection）、记忆（Tracking）和方向感（Centering）。

---

## 🎬 序幕：我们在解决什么问题？

想象一个简单场景：你站在笔记本摄像头前，打了一个视频通话。你往左走几步，画面里你的脸就偏到了边缘——对方看到的是一个歪歪扭扭的画面。

**核心问题：** 能不能让摄像头「智能」地跟上人的位置，自动指挥摄像头（或裁剪画面）让人始终保持在画面正中央？

要做到这一点，需要**三层堆叠能力**：

| 层级 | 能力 | 类比 |
|------|------|------|
| **第一层** | 检测 (Detection) — 每一帧找到人在哪 | 眼睛：看到人在哪里 |
| **第二层** | 追踪 (Tracking) — 跨帧知道是「同一个人」| 记忆：记住这是刚才那个人 |
| **第三层** | 居中控制 (Centering) — 计算偏差并下达指令 | 方向感：告诉摄像头该往哪移 |

> 💡 这就是典型的 Machine Vision 系统流水线 (Pipeline)：感知 → 理解 → 行动。

---

## 📚 第一章：感知层——目标检测 (Object Detection)

### 1.1 一句话定义

**目标检测 (Object Detection)** = 给定一帧图像，输出所有目标的**边界框 (Bounding Box)** + **类别标签 (Class Label)** + **置信度 (Confidence Score)**。

### 1.2 使用的模型：RTMDet-s

本项目使用 **mmdetection** 框架中的预训练 **RTMDet-s** 模型。

| 属性 | 说明 |
|------|------|
| 框架 | mmdetection (OpenMMLab) |
| 模型 | RTMDet-s (Real-Time Models for Detection, small variant) |
| 预训练 | COCO 数据集，80 类 |
| 目标类别 | 只保留 `person`（label = **0**） |

> 💡 `RTMDet` 是 OpenMMLab 2023 年推出的轻量高效检测器，"s" 代表 small 版本，适合实时推理场景。比 YOLO 系列在同等速度下精度更高。

### 1.3 关键操作

1. **输入**: 摄像头每一帧图像
2. **推理**: `RTMDet-s` 输出所有检测到的目标
3. **过滤**: 只保留 `class == 0`（person 类），丢弃其他（车、动物等）

### 1.4 ❗ 检测的致命问题——帧间断裂

单帧检测只能告诉你「这一帧有人」，但不能告诉你「这个人和上一帧的人是同一个人吗？」

- 帧 1：检测到一个人 → 框坐标 (100, 200, 300, 400)
- 帧 2：检测到一个人 → 框坐标 (105, 198, 305, 402)
- **问题**：这两个框对应的是同一个人吗？还是一个人离开、另一个人进来了？

> 🔑 **故事转折点：** 纯检测 (Detection) 没有「身份记忆」——它只能逐帧看到人，却不知道前后帧是不是同一个人。→ 我们需要 **追踪 (Tracking)** 能力！

## 🎭 第二章：理解层——目标追踪 (Object Tracking)

### 2.1 一句话定义

**目标追踪 (Object Tracking)** = 在连续帧之间，为每个检测到的目标分配一个**持久 ID (Track ID)**，使系统知道「帧 1 的人 A = 帧 2 的人 A」。

### 2.2 使用的算法：ByteTrack

本项目推荐使用 **ByteTrack** 追踪器（而非 mmtracking）。

| 属性 | 说明 |
|------|------|
| 算法 | ByteTrack |
| 输入 | 检测器输出的边界框 + 置信度 |
| 输出 | 每个框附加唯一的 Track ID |
| 特点 | 同时利用低置信度和高置信度检测结果 |

> 💡 ByteTrack 的核心创新是**不丢弃低置信度检测**。传统追踪器只用高置信度框匹配，ByteTrack 先匹配高置信度框，再用剩余的低置信度框做二次匹配——因此能在遮挡、模糊场景下保持追踪连续性。

### 2.3 单人简化假设

项目做了一个重要简化：

- **假设画面中只有一个人**
- 如果检测到多个人 → 取**边界框面积最大**的那个人
- 面积 = `(box_width) × (box_height)`

> 💡 为什么用面积最大？离摄像头最近的人通常在画面中占的面积最大。这是一种简单但有效的启发式：「最大的就是最重要的」。

### 2.4 此时的系统能力

经过检测 + 追踪，系统已能：

- ✅ 从摄像头获取实时流
- ✅ 每帧检测出 person 目标
- ✅ 给检测到的人分配持久 ID
- ✅ 在画面上显示边界框和 ID

### 2.5 ❗ 追踪的局限——只管「认识」不管「居中」

追踪告诉了我们「这是 Track #1 的那个人，他在画面的左下角」，但系统仍然**不知道该怎么做**——人偏了，摄像头该往哪移？移多少？

> 🔑 **故事转折点：** 追踪解决了「身份」问题，但还缺少「行动决策」——我们需要 **居中控制逻辑 (Centering Logic)** 来弥合感知和行动之间的鸿沟！

---

## 🏆 第三章：行动层——居中控制 (Centering Control)

### 3.1 一句话定义

**居中控制 (Centering)** = 计算「人在哪」和「画面中心在哪」的偏差，然后告诉摄像头「向左/右/上/下移动 N 个像素」。

### 3.2 算法步骤

```
Step 1: 计算图像中心
        image_center_x = width / 2
        image_center_y = height / 2

Step 2: 计算人物边界框中心
        box_center_x = box_left + box_width / 2
        box_center_y = box_top + box_height / 2

Step 3: 计算水平偏差
        dx = box_center_x - image_center_x
        if dx < 0 → 人在左边 → 摄像头向左移 |dx| 像素 (绿色提示)
        if dx > 0 → 人在右边 → 摄像头向右移 |dx| 像素 (绿色提示)

Step 4: 计算垂直偏差
        dy = box_center_y - image_center_y
        if dy < 0 → 人在上方 → 摄像头向上移 |dy| 像素 (红色提示)
        if dy > 0 → 人在下方 → 摄像头向下移 |dy| 像素 (红色提示)
```

### 3.3 具体例子

假设画面分辨率 640×480：

| 参数 | 值 |
|------|-----|
| 图像中心 | (320, 240) |
| 人物边界框 | left=50, top=100, width=200, height=300 |
| 框中心 | (50 + 200/2, 100 + 300/2) = **(150, 250)** |
| dx | 150 − 320 = **−170** → 人偏左 170px |
| dy | 250 − 240 = **+10** → 人偏下 10px |

**输出指令：**
- 🟢 `Camera must move LEFT by 170 pixels`
- 🔴 `Camera must move DOWN by 10 pixels`

### 3.4 颜色约定

| 方向 | 颜色 | 含义 |
|------|------|------|
| 水平 (Left/Right) | 🟢 绿色 (Green) | 水平调整 |
| 垂直 (Up/Down) | 🔴 红色 (Red) | 垂直调整 |

> 💡 颜色的设计意义：绿色（安全/常见调整）vs 红色（注意/需要纠正）。水平偏移在正常走动中更频繁，垂直偏移通常意味着人站起或蹲下——颜色区分帮助快速识别偏移类型。

## 🗺️ 全局回顾：系统流水线架构

```
┌──────────────────────────────────────────────────────────────┐
│            CST8508 期末项目 — 人物追踪居中系统                   │
│                                                              │
│  📹 Webcam Stream (Lab 5 方法)                                │
│          │                                                   │
│          ▼                                                   │
│  👁️ Layer 1: Object Detection (RTMDet-s)                     │
│    ✅ 每帧找到所有 person 的 bounding box                      │
│    ❌ 不知道跨帧是否是同一个人                                  │
│          │                                                   │
│          ▼                                                   │
│  🧠 Layer 2: Object Tracking (ByteTrack)                     │
│    ✅ 给每个人分配持久 Track ID                                │
│    ✅ 多人时取面积最大的那个                                    │
│    ❌ 不知道人偏了多少、摄像头该怎么动                           │
│          │                                                   │
│          ▼                                                   │
│  🎯 Layer 3: Centering Control                               │
│    ✅ 计算人物框中心 vs 图像中心的偏差                           │
│    ✅ 输出方向 + 偏移量 (颜色编码)                              │
│          │                                                   │
│          ▼                                                   │
│  📺 Display: 画面 + 检测框 + ID + 方向指令                      │
└──────────────────────────────────────────────────────────────┘
```

### 层级过渡总结

| 从 → 到 | 解决了什么核心问题？ |
|---------|---------------------|
| Webcam → Detection | 从原始像素中「看到」人在哪（边界框 + 置信度） |
| Detection → Tracking | 从单帧快照到跨帧「记住」这是同一个人（Track ID） |
| Tracking → Centering | 从「我知道人在哪」到「我知道摄像头该怎么动」（偏差 + 指令） |
