# Week 11 故事线：关联规则挖掘 (Association Rule Mining)

> **Source:** `Week11_Association Rule Mining.pdf`
> **核心主题：** 如何从海量交易记录中，自动发现"买了 A 的人往往也会买 B"这样的隐藏规律？
> **故事线：** 从暴力穷举（不可能完成的任务）→ 两步解耦（拆分问题）→ Apriori 原理（智能剪枝）→ 候选生成与规则输出（工程落地）

---

## 🎬 序幕：我们在解决什么问题？

想象一下你是沃尔玛超市的数据分析师。每天有成千上万的顾客结账，每张收据上列着不同的商品。你的老板问了一个看似简单的问题：**"哪些商品经常被一起购买？"**

这个问题的答案价值巨大：
- 如果发现"买尿布的人往往也买啤酒"，就可以把它们摆在一起（这是零售业真实的经典案例）。
- 如果发现"买面包+牛奶的客户也倾向于买鸡蛋"，就可以定向推送优惠券。

用数学语言来描述，我们要找的是 **关联规则 (Association Rule)**：形如 `{尿布} → {啤酒}` 的蕴含表达式，表示"买了左边的商品，就很可能也会买右边的商品"。

> ⚠️ **关键警告：** 这里的"→"代表的是**共现 (Co-occurrence)**，不是**因果 (Causality)**！买尿布不会"导致"买啤酒，只是说它们经常同时出现在同一张收据上。

那么，如何从数据中把这些有趣的规则筛选出来呢？第一步，我们需要定义"有趣"的数学标准。

> 🔑 **故事转折点：** 问题清晰了，但没有度量标准就无法筛选。我们需要先建立一套精确的数学语言来衡量一条规则"够不够好"。

---

## 📚 第一章：数学基础——支持度与置信度

### 1.1 三个核心定义

为了量化"哪些商品经常一起出现"，我们需要三个递进的概念：

**① 项集 (Itemset)** —— 一个或多个商品的集合。
- 例：`{Milk}` 是 1-项集，`{Milk, Bread, Diaper}` 是 3-项集。

**② 支持度 (Support)** —— 一个项集在所有交易中"有多常见"。
- `s(X) = 包含 X 的交易数 / 总交易数`
- 例：在5笔交易中，`{Milk, Bread, Diaper}` 出现了2次 → `s = 2/5 = 0.4`

**③ 置信度 (Confidence)** —— 一条规则"有多可靠"。
- `c(X → Y) = σ(X ∪ Y) / σ(X)` = 同时含有 X 和 Y 的交易数 / 含有 X 的交易数
- 例：`c({Milk, Diaper} → {Beer}) = 2/3 = 0.67`，表示"买了牛奶和尿布的顾客中，有67%也买了啤酒"。

> 💡 **类比理解：**
> - **支持度** 好比一道菜的"人气指数"——在菜单上被点的总比例。太冷门的菜（支持度太低）即使每次被点都好评如潮，也不值得占菜单位置。
> - **置信度** 好比一道菜的"复购率"——点了前菜 A 的人中有多大比例会追加甜品 B。

### 1.2 挖掘目标

关联规则挖掘的目标明确了：

**找出所有同时满足以下条件的规则 X → Y：**
1. `support(X ∪ Y) ≥ minsup`（这个组合足够常见）
2. `confidence(X → Y) ≥ minconf`（这个推断足够可靠）

> 🔑 **故事转折点：** 目标清晰了！最直接的方法就是暴力穷举——列出所有可能的规则，逐一检验。但这行得通吗？

---

## 🎭 第二章：暴力穷举——一个注定失败的方案

### 2.1 穷举法的想法

最直觉的做法：
1. 列出所有可能的关联规则
2. 对每条规则计算支持度和置信度
3. 保留通过阈值的规则

### 2.2 ❗ 指数爆炸——为什么不可能

让我们算一算到底有多少种可能的规则。

给定 `d` 个不同的商品：
- 所有可能的项集数量：`2^d`（每个商品要么选要么不选）
- 所有可能的关联规则数量：`R = 3^d − 2^(d+1) + 1`

| d（商品数） | 项集数 | 规则数 |
| :---: | :---: | :---: |
| 6 | 64 | 602 |
| 10 | 1,024 | ~57,000 |
| 20 | ~100万 | ~35亿 |

仅 6 个商品就有 602 条候选规则！一个普通超市可能有 **10,000+** 种商品，穷举法所需的规则数量天文般不可想象。

> 🔑 **故事转折点：** 暴力法彻底失败——搜索空间随商品数指数爆炸。我们必须找到一种方法来大幅裁剪搜索空间。一个关键观察将为我们打开突破口！

---

## 📖 第三章：两步法——将大问题一分为二

### 3.1 核心观察（最精妙的洞察！）

仔细观察同一个频繁项集 `{Milk, Diaper, Beer}` 产生的所有规则：

| 规则 | 支持度 | 置信度 |
| :--- | :---: | :---: |
| {Milk, Diaper} → {Beer} | **0.4** | 0.67 |
| {Milk, Beer} → {Diaper} | **0.4** | 1.0 |
| {Diaper, Beer} → {Milk} | **0.4** | 0.67 |
| {Beer} → {Milk, Diaper} | **0.4** | 0.67 |
| {Diaper} → {Milk, Beer} | **0.4** | 0.5 |
| {Milk} → {Diaper, Beer} | **0.4** | 0.5 |

发现了吗？**支持度全部相同！** 只有置信度不同。

这意味着我们可以把问题**解耦**为两个独立的步骤：
1. **先找项集**：只关注支持度，找出所有"足够常见"的频繁项集
2. **再切规则**：对每个频繁项集，把它切成不同的 X → Y 分法，只保留置信度达标的

### 3.2 两步法框架

```text
Step 1: 频繁项集生成 (Frequent Itemset Generation)
        → 找出所有 support ≥ minsup 的项集

Step 2: 规则生成 (Rule Generation)
        → 对每个频繁项集做二元划分，保留 confidence ≥ minconf 的
```

> 💡 **类比：** 就像找对象。Step 1 = 海选（先把月薪太低的筛掉），Step 2 = 精选（在通过海选的人里看性格、三观是否匹配）。海选用一个粗指标快速缩小范围，精选用一个细指标逐一验证。

### 3.3 ❗ 但瓶颈还在！

两步法把搜索空间从"规则空间"缩小到了"项集空间"，但 Step 1 中频繁项集生成本身仍然是指数级的（`2^d` 个候选），暴力检查仍然行不通。

- **暴力 Step 1 的复杂度：** O(NMw)，其中 N = 交易数、M = 2^d（候选数）、w = 平均交易宽度。

> 🔑 **故事转折点：** 两步法把问题拆开了，但核心瓶颈（频繁项集生成）还没解决。我们急需一个能大幅裁减 `2^d` 候选的方法。**Apriori 原理**就是这把锋利的剪刀！

---

## 🏆 第四章：Apriori 算法——智能剪枝的胜利

### 4.1 Apriori 原理（反单调性）

整个 Apriori 算法建立在一条优雅而强大的数学性质上：

> **Apriori 原理：** 如果一个项集是频繁的，那么它的**所有子集**也一定是频繁的。
>
> 数学表达：`∀X, Y : (X ⊆ Y) ⇒ s(X) ≥ s(Y)`
>
> 即：一个项集的支持度**永远不会超过**其子集的支持度。

这被称为**支持度的反单调性 (Anti-monotone Property)**。

> 💡 **直觉理解：** 如果"买牛奶"的人只有40%，那么"同时买牛奶和面包和尿布"的人只会更少，不可能更多。集合越大，限制越多，满足条件的交易越少。

**逆否命题（真正的杀手锏）：**
如果一个项集是**不频繁的**，那么包含它的**所有超集都不可能频繁**——可以**直接全部剪掉**！

### 4.2 逐步推演：Apriori 如何工作

用课堂上的购物篮数据（5笔交易、6种商品、minsup = 3）演示完整流程：

**第1轮：扫描数据库，统计 1-项集**

| Item | Count | 频繁？ |
| :--- | :---: | :---: |
| Bread | 4 | ✅ |
| Coke | 2 | ❌ 剪掉 |
| Milk | 4 | ✅ |
| Beer | 3 | ✅ |
| Diaper | 4 | ✅ |
| Eggs | 1 | ❌ 剪掉 |

→ Coke 和 Eggs 被淘汰。根据 Apriori 原理，**任何包含 Coke 或 Eggs 的组合都不需要再考虑**！

**第2轮：从存活的 4 个频繁 1-项集生成候选 2-项集**

只有 C(4,2) = 6 个候选（而非 C(6,2) = 15 个）：
`{Bread,Milk}`, `{Bread,Beer}`, `{Bread,Diaper}`, `{Beer,Milk}`, `{Milk,Diaper}`, `{Beer,Diaper}`

→ 再次扫描数据库，统计支持度，淘汰不达标的。

**第3轮：从存活的频繁 2-项集生成候选 3-项集**，以此类推……

**裁剪效果惊人：** 如果不剪枝，需要检查 `6 + 15 + 20 = 41` 个候选；使用 Apriori 剪枝后，只需检查 `6 + 6 + 4 = 16` 个候选——**裁减了60%以上**！

### 4.3 Apriori 算法的完整伪代码

```text
k = 1
F₁ = {所有支持度 ≥ minsup 的 1-项集}

Repeat until F_k 为空:
    (1) 候选生成:   从 F_k 生成 L_{k+1}
    (2) 候选剪枝:   如果 L_{k+1} 中某个候选的任何 k-子集不在 F_k 中 → 剔除
    (3) 支持度计数: 扫描数据库，计算 L_{k+1} 中每个候选的支持度
    (4) 候选淘汰:   保留支持度 ≥ minsup 的 → F_{k+1}

    k = k + 1
```

### 4.4 候选生成的具体方法

Apriori 算法中"候选生成"有两种经典策略：

**方法 A：F_{k-1} × F_{k-1}（前缀合并法）**
- 规则：两个 (k-1)-项集共享前 (k-2) 个元素时才合并
- 例：Merge(ABC, ABD) = ABCD ✅
- 例：Merge(ABD, ACD) 不合并（前缀不匹配）❌

**方法 B：替代 F_{k-1} × F_{k-1}（后缀-前缀合并法）**
- 规则：第一个项集的后 (k-2) 个元素等于第二个项集的前 (k-2) 个元素
- 例：Merge(ABC, BCD) = ABCD ✅
- 例：Merge(ABD, BDE) = ABDE ✅

两种方法初始候选数可能不同，但经过候选剪枝后结果一致（都只保留真正可能频繁的候选）。

### 4.5 候选剪枝示例

设 F₃ = {ABC, ABD, ABE, ACD, BCD, BDE, CDE}

使用前缀合并法生成 L₄ = {ABCD, ABCE, ABDE}，然后剪枝：
- ABCE → 检查子集 ACE ∉ F₃ → ❌ 剪掉
- ABDE → 检查子集 ADE ∉ F₃ → ❌ 剪掉
- **最终：L₄ = {ABCD}** — 仅存活1个候选！

## 📹 第五章：规则生成——最后一步

频繁项集找到之后，需要把每个频繁项集"切"成规则。

给定一个大小为 k 的频繁项集 L，一共有 **2^k − 2** 种切法（排除 L→∅ 和 ∅→L）。

例：若 L = {A, B, C, D}，候选规则有 14 条：
```text
3→1: ABC→D, ABD→C, ACD→B, BCD→A
2→2: AB→CD, AC→BD, AD→BC, BC→AD, BD→AC, CD→AB
1→3: A→BCD, B→ACD, C→ABD, D→ABC
```

对每条规则计算置信度，保留 ≥ minconf 的即可。

由于这些规则共享相同的支持度（来自同一个频繁项集），支持度只需查表，计算开销主要在置信度上。

## 🗺️ 全局回顾：技术演进路线图

```text
┌──────────────────────────────────────────────────────────┐
│ 关联规则挖掘技术演进路线图                                │
│                                                          │
│         暴力穷举法                                       │
│         ✅ 理论可行，简单粗暴                            │
│         ❌ 规则数 = 3^d，指数爆炸，完全不可行            │
│                  │                                       │
│                  ▼  (观察：同源规则支持度相同)            │
│         两步法：先找项集、再生成规则                      │
│         ✅ 将规则空间缩减为项集空间                      │
│         ❌ 项集空间仍是 2^d，暴力扫描太慢                │
│                  │                                       │
│                  ▼  (发现：支持度的反单调性)              │
│         Apriori 算法（逐层 + 智能剪枝）                  │
│         ✅ 不频繁子集的所有超集直接剪掉                  │
│         ✅ 候选数从 41 → 16（裁减 60%+）                 │
│         ⚠️ 每一层仍需完整扫描一次数据库                  │
│                  │                                       │
│                  ▼  (扩展方向)                            │
│         FP-Growth, Hash Tree 等高级方法                   │
│         ✅ 无需候选生成，进一步提速                      │
└──────────────────────────────────────────────────────────┘
```

**关键概念对比：**

| 维度 | 暴力穷举 | 两步法（无剪枝） | Apriori 算法 |
| :--- | :--- | :--- | :--- |
| **搜索空间** | 3^d 条规则 | 2^d 个项集 | 逐层缩减 |
| **核心策略** | 无 | 支持度/置信度解耦 | 反单调性剪枝 |
| **数据库扫描** | 极多次 | 每层一次 | 每层一次 |
| **可行性** | ❌ d>10 崩溃 | ❌ 仍太慢 | ✅ 实际可用 |

**两步法的解耦逻辑：**

| 从 → 到 | 解决了什么核心问题？ |
| :--- | :--- |
| 暴力法 → 两步法 | 发现同一频繁项集的所有规则共享支持度，因此可以先找项集再切规则 |
| 两步法 → Apriori | 利用支持度的反单调性，一旦发现某子集不频繁，其所有超集立即剪枝 |
| Apriori → FP-Growth | **课外扩展**：避免多次数据库扫描，用压缩的 FP-Tree 一次建树 |
