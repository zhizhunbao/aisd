## DIM-2: Concepts（核心概念）

固定章节编号：

```

白话定义段落。

（每个术语用 ### 三级标题，中英文并列，下方段落定义，末尾 > 标注易混淆项）

### A vs B
| 维度 | A | B |
|------|---|---|
| **本质** | ... | ... |

> 📖 来源引证

### C vs D
...

## 核心属性

### 信息架构
（用 ┌───┤ box-drawing 图展示层次结构）
```

- ✅ 末尾用 `> 易混淆：` 标注容易搞混的项

## DIM-7: Pitfalls（踩坑记录）

**固定格式，每个坑的结构严格一致：**

```
# {Topic} 踩坑记录

> ⚠️ **这是知识库中最有价值的维度。** 每次踩坑后请追加条目。

---


## 坑 N: {坑标题}

**场景：** {什么情况下会遇到}

**症状：** {用户看到的现象}

**根因：** {为什么会发生}

**解法：**

❌ 错误写法 — 原因

    错误代码（4 空格缩进，绝不嵌套代码块）

✅ 正确写法 — 原因

    正确代码（4 空格缩进）

**教训：** {一句话总结}

> 📖 Docs: [来源](URL) — 章节

---

（每个坑之间 `---` 分隔，格式完全一致）


## 调试清单

1. [ ] **检查项 1？** → 操作建议
2. [ ] **检查项 2？** → 操作建议
...
```

**关键格式规则：**
- ✅ 用 **加粗关键词**（场景/症状/根因/解法/教训）+ 同行内容
- ❌ 不用 `###` 三级标题
- ✅ 解法用 ❌/✅ + 4 空格缩进
- ❌ 绝不在 ` ```markdown ` 中嵌套 ` ```bash `
- ✅ 每个坑结尾有 `> 📖` 引证
- ✅ 调试清单中的检查项用 **加粗**

> 📖 参考: `claude_code_skill_pitfalls.md` — 10 坑 + 调试清单

## DIM-8: History（历史演进 — 故事线风格）

**使用故事线叙事风格**，用章节 (📚) 讲述技术演进，每章有转折点 (🔑)。

固定格式：

```
# {Topic} 的故事线：从 {起点} 到 {终点}

> **核心主题：** 一句话概括技术演进的核心线索
> **故事线：** 一个不断"打怪升级"的问题解决历程

---

## 🎬 序幕：一切从什么问题开始？

### 一句话概括
> 用引用块写出核心问题

（交代背景，为什么这个问题重要）

> 🔑 **问题提出：** 引出第一章的核心问题

---

## 📚 第一章：{章节标题}（年代）

> **关键人物：** 姓名
> **关键论文：** 引用

### 发生了什么？
（用叙事语言讲故事，可用 ASCII 图辅助）

### 为什么这很重要？
（解释影响）

### 但还有一个问题……
（局限性，引出下一章）

> 🔑 **故事转折点：** 一句话引出下一章

---

## 📚 第二章：{章节标题}（年代）
（同上格式，编号连续）

---

## 🗺️ 全局回顾：技术演进路线图
（ASCII box-drawing 图总结所有章节的演进关系）

### 每一步升级解决了什么问题？
| 从 → 到 | 解决了什么核心问题？ |
|----------|-------------------|
```

**关键格式规则：**
- ✅ 用 `🎬 序幕` + `📚 第N章` 作为章节标题
- ✅ 每章结尾用 `🔑 **故事转折点：**` 引出下一章
- ✅ 叙事口吻讲故事，不是干巴巴列事实
- ✅ 每章有 **关键人物** 和 **关键论文**
- ✅ 末尾有 `🗺️ 全局回顾` 总结路线图
- ❌ 不要用 Station 格式（改用章节叙事）

> 📖 参考: 用户 storyline 格式 (lecture_storyline.md)

## 质量检查清单

生成完所有文件后，逐项检查：

- [ ] **R1 Frontmatter** — 每个文件都有完整 frontmatter（6 个必填字段）
- [ ] **R2 引证** — 每个 `##` 章节结尾都有 `>` 引证块
- [ ] **R3 无嵌套** — 没有在 ` ```markdown ` 中嵌套代码块
- [ ] **R4 对比格式** — ❌/✅ 用缩进，不用代码块包裹
- [ ] **R5 分隔线** — `##` 之间有 `---`，`###` 之间没有
- [ ] **R6 标题引证** — `# 标题` 下紧跟全局引证行
- [ ] **章节编号** — Map 7章 / Concepts 5章 / Math 5章 / Tutorial 6 Section / Usage 场景+速查 / Code 4章 / Pitfalls 坑+清单 / History Station / Bridge 6表
- [ ] **关键词格式** — Pitfalls 用 **加粗关键词**，History 用 **问题/创新/局限**
- [ ] **表格一致** — 术语/辨析/速查/文件地图都用 Markdown 表格
- [ ] **Box-drawing** — 架构图用 `┌───┤` 风格，不用 Mermaid
- [ ] **文件命名** — `{topic}_{dimension}.md`
