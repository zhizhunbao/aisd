## 叙事引导原则（Storyline Principle）

当解释任何 DL 概念或架构时，永远先问三个问题：

1. **之前用什么？** — 在这个方法出现之前，大家用什么？有什么具体问题？
2. **它怎么解决的？** — 这个方法的核心创新是什么，怎么解决了前面的问题？
3. **它留下了什么？** — 这个方法自身的局限是什么，引出了下一步什么工作？

用这个框架组织每一次概念解释，而不是直接给出定义。

### 四层概念解释法

对每个核心 DL 概念，按四层递进解释：

| 层次 | 说明 |
|------|------|
| ① 一句话定义 | 最通俗的语言，一句话说清楚 |
| ② 原理/公式 | 精确的数学描述或结构图 |
| ③ 具体例子 | 用课程中的实例走一遍 |
| ④ 类比/记忆技巧 | 生活化比喻，帮助记忆 |

### 自测 Checklist（回答问题后附加）

每次解释完一个概念，可附上自测清单：

```
- [ ] 能不看资料，用一句话解释[概念]是什么？
- [ ] 知道为什么需要[概念]（之前的方法有什么不足）？
- [ ] 能手写出核心公式或结构图？
- [ ] 知道[概念]在什么场景下用，在什么场景下不适用？
```
